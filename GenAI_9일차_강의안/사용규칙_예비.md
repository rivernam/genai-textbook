# 에이전트 사용 규칙 (1쪽) · 예비본

이 파일은 8일차 미션 3 마무리에서 사용규칙.md를 남기지 못한 분을 위한 예비본입니다.
8일차 미션 폴더(day08-m1)의 tilt-report-pack 설정을 기준으로 미리 채워 두었습니다. 9일차에 이 파일을 사용규칙.md로 이름을 바꿔 쓰고, 아래에 「막지 못한 것」과 「사고 시 연락처」 두 줄을 더합니다.

대상: tilt-report-pack (틸트 조치 보고서 스킬 · 작성/검토 서브에이전트 · 결재함 훅), 후공정 1팀과 2팀

## 자료
### 넣어도 되는 자료
- 틸트 검사 결과 csv(data/<설비>_<YYYYMMDD>.csv: 스트립, 제품군, 틸트 측정값)
- 설비 문서(docs7/의 매뉴얼, 안전규정, SOP, 공지, 회의록)
### 가공 후에만 넣을 자료
- 사람 이름, 사번, 연락처가 들어간 회의록·메일: 이름과 연락처를 지운 뒤
- 실제 설비 ID와 고객사 제품명: 실습용 가상 이름으로 바꾼 뒤
### 금지 자료
- 키, 비밀번호, 접속 주소 같은 인증 정보
- 고객 정보와 계약 문서, 인사 정보

## 권한 규칙
- 묻지 않고 실행: python tools/ 아래 도구(grade_tilt, search_docs, send_report, 검사 스크립트), python .claude/skills/ 아래 스크립트, out/ 폴더 쓰기
- 그 밖의 명령과 파일 쓰기: 실행 전에 권한을 묻습니다(대화형). claude -p 실행에서는 묻지 않고 거부됩니다
- 훅: 도구를 실행할 때마다 기록(logs/agent_log.jsonl), send_report 직전에 검토 기록 확인(검토를 통과하지 않은 보고서는 결재함에 보내지 않음)
- 받은 폴더는 처음 열 때 신뢰 질문의 ⚠ 줄(미리 허용한 명령, 훅)을 읽고 정합니다

## 검토 규칙
- 보고서는 report-reviewer가 원본 csv와 설비 문서로 등급, 조치, 건수, 인용을 다시 확인하고 「통과」가 나온 뒤에만 결재함에 보냅니다
- 「보완」이면 report-writer가 원본 csv에서 다시 만들고 다시 검토합니다. 최대 2번까지, 그래도 통과하지 못하면 멈추고 사람에게 알립니다
- 사람이 확인하는 지점: 결재함(outbox)의 보고서를 결재하기 전, 보류(OUT) 건의 품질팀 통보

## 공유 범위
- 공유 범위: 팀(후공정 1팀, 2팀)
- 이유: 같은 검사 양식과 설비 문서를 쓰는 팀끼리만 결과가 맞습니다
- 누가 고치나: 스킬과 서브에이전트는 1팀 담당자, 각 팀의 data와 outbox는 그 팀
- 팀 공용(.claude/settings.json)에 둘 것: 허용 목록, 기록 훅, 결재함 훅 / 개인(settings.local.json)에 둘 것: 모델 선택 같은 개인 설정
- IT에 요청할 것: 사내 결재 시스템과 연결할 때의 계정과 권한
