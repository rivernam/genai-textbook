## 확인한 사실(2026-11 공식 문서)

1. 단가: Haiku 5.5 0.10/0.50달러(10만 토큰 이하), Sonnet 5.5 2/10, Opus 5.5 4/20. 캐시 읽기 Haiku 0.01, Sonnet 0.10, Opus 0.20. 캐시 쓰기 1.25배(5분), 2배(1시간). (Pricing, Prompt caching)
2. `usage.output_tokens_details.thinking_tokens`: 출력 토큰 가운데 thinking 토큰 수, output_tokens에 포함. (Messages API 레퍼런스)
3. 토큰 세기는 무료, 분당 요청 수 상한이 따로 있음, 값은 추정값. (Token counting)
4. effort: output_config.effort, low~max. Haiku 5.5와 Opus 5.5 기본 medium, 그 밖은 high. 모든 출력 토큰에 작용. 엄격한 상한이 아님. (Effort)
5. 레이트 리밋: RPM, ITPM, OTPM, 토큰 버킷, 429와 retry-after, 월 사용 한도의 429에는 retry-after 없음. (Rate limits)
6. SDK 재시도: 연결 실패, 타임아웃, 408, 409, 429, 500 이상. 기본 2회, 타임아웃 10분. (Errors, SDK 문서)
7. 캐시 최소 길이 512토큰(현행 모델). (Prompt caching)
8. OpenAI SDK 3.16.2의 `completion_tokens_details.reasoning_tokens`. (설치된 SDK 소스)

## 사용자에게 확인할 것

2026-11-27 사용자가 확인함(추천안대로 유지).

1. 프롬프트 캐싱은 `llm.py`가 지원하지 않아 예제 없이 그림과 수치로만 설명했다. 예제가 필요하면 `llm.py`에 캐싱 옵션과 캐시 토큰 수를 더해야 한다.
2. effort는 `llm.py`에 없으므로 예제 5-1(SDK 직접 호출)에서만 보여 준다.
3. 병렬 처리(강의 p.90~93)는 다루지 않았다. 관통 프로젝트 이후 단계에서 다룰지 정한다.

## 빠진 주제에 대한 결정(2026-11-27)

사용자가 넣을지 판단을 맡겼다.

- 병렬 처리: 넣는다. 원래 설계에서 "구현은 관통 프로젝트로" 미뤘지만 어느 단계에도 들어가지 않았고, 10장 코드가 "(5장)"을 가리키며 이미 병렬 처리를 쓰고 있었다. LLM API에 고유한 원리(응답 시간이 출력 토큰 생성 시간이라 대기가 겹친다, 병렬 수가 레이트 리밋과 직결된다)가 있다. 본문에 "여러 요청을 병렬로 보내기" 절, 학습 목표 4 보강, 자가점검 6번을 더했다. 구현 실습은 관통 프로젝트 2단계에 더한다(API 키가 있는 세션에서 실행 필요, 아직 하지 않음).
- 프롬프트 캐싱 예제: 넣지 않는다. 원리, 단가, 조건은 본문과 실습 5-1에 이미 있다. 예제를 두려면 공통 코드 llm.py에 캐싱 옵션을 더해야 하고, 그 예제는 Anthropic API에서만 실행되어 사내 API로 실행하는 독자는 볼 수 없다.
