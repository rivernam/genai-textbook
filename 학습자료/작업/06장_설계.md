## 확인한 사실

1. Anthropic 구조화 출력: constrained decoding, compiled grammar, 첫 요청 지연과 24시간 캐시, 지원하지 않는 키워드(minimum, maximum, minLength 등)는 400, additionalProperties false 필수, refusal과 max_tokens는 스키마에 맞지 않을 수 있음, enum 대소문자 비보장, 필수 필드가 먼저. (Structured outputs, 2026-11)
2. Willard & Louf (2023) arXiv:2307.09702: 정규 표현식, 문법을 상태 기계로 바꿔 허용 토큰을 찾는 방법.

## 사용자에게 확인할 것

2026-11-27 사용자가 확인함(추천안대로 유지).

1. 예제 6-2는 1장의 PC 모델(약 1GB)을 다시 쓴다. 준비 셀에서 미리 내려받지 않고 예제 안에서 불러오게 했다(프로젝트 노트북이 모델을 내려받지 않도록).
2. 엑셀, DB 저장과 기본 키, upsert(강의 p.207~233)는 6장에 넣지 않았다. 관통 프로젝트 이후 단계에서 다룰지 정한다.
3. pydantic(messages.parse)은 넣지 않았다. 스키마를 dict로 작성하는 방식만 다룬다.

## 빠진 주제에 대한 결정(2026-11-27)

- 엑셀, DB 저장, 기본 키, upsert: 넣는다. 원래 설계에서 "저장은 관통 프로젝트로" 미뤘지만 어느 단계에도 들어가지 않았다. LLM 결과를 저장할 때 생기는 문제(실패한 건만 다시 보내기, 실행마다 다른 결과를 구분하기)는 이 교재의 주제와 이어진다. 본문에 "결과를 저장하기" 절, 학습 목표 5, 자가점검 6번을 더했다. 엑셀과 SQLite 사용법 자체는 생성형 AI 주제가 아니므로 본문에서는 원리만 쓰고, 구현은 관통 프로젝트 2단계 실습에 더한다(API 키가 있는 세션에서 실행 필요, 아직 하지 않음).

## 관통 프로젝트 2단계에 병렬 처리와 저장을 더함(2026-11-27)

- P2 상자에 둘째 셀을 더했다. `open_db()`, `save_result()`(번호 기본 키, `ON CONFLICT(번호) DO UPDATE`), `run_batch()`(저장된 결과가 없거나 "실패"인 건만 `ThreadPoolExecutor`로 보내고, `pool.map()`에서 꺼내는 대로 메인 스레드에서 저장). SQLite 연결은 만든 스레드에서만 쓸 수 있어 저장을 메인 스레드에 두었다.
- 실패를 흉내 내는 mock 대신, 1회를 앞 8건만 넘기고(중간에 멈춤) 2회 전에 Q21의 행을 "실패"로 바꾸는 방식으로 다시 보내기를 보여 준다. 요금이 들지 않는 SQL 한 줄이라 독자가 무엇을 흉내 냈는지 바로 보인다.
- 6장 본문의 "잘림과 거절은 다시 보내지 않는다"에 맞춰, 1단계의 "확인 필요"는 2단계에서 "사람 확인"으로 바꿨다(전에는 "실패"). "실패"만 다시 보낸다.
- 6장 본문이 남기라고 한 실제 모델 이름을 저장하려고 1단계 `answer()`의 결과 dict에 `model`(`Reply.model`)을 더했다.
- 병렬 시간은 순차 실행을 따로 하지 않고(요금 두 배), 요청마다 잰 시간의 합과 전체 실행 시간을 비교한다.
