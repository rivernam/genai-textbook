## 2. 두 층의 내용

- **일반 층**: 공정이 무엇을 하는지, 왜 하는지. 교육 자료(EDU-001, 004~007, 010)와 각 문서의 목적 절에 있다. 모델이 검색 없이도 아는 내용이다.
- **회사 층**: 관리 기준값, 담당 부서, 점검 주기, 개정 이력, 사내 약어, 사람, 내선 번호, 설비 번호, 알람 코드. 모두 지어냈다. 이 층을 묻는 질문은 검색해야만 답할 수 있다.

일반 층에 넣은 업계 표준값은 7절에서 공개 자료로 확인했다. 회사 층의 값은 업계 표준과 어긋나지 않게 정했다(예: 사내 손목띠 기준 10MΩ 이하는 업계 표준 35MΩ 미만보다 엄격하다). 문서 안에서 표준값과 사내값이 함께 나오는 곳은 "업계 표준", "사내 기준"을 문장에 밝혔다.

## 5. 평가셋

- 질문의 말투는 현장 문의처럼 썼다. 문서의 낱말을 그대로 쓰는 질문(사실)과 일부러 다른 낱말을 쓰는 질문(바꿔 말함)을 나눴다.
- `evidence`는 정답 문서에서 답이 적힌 문장을 그대로 옮긴 것이다. 검사는 공백과 표의 세로줄(`|`)을 모두 뺀 뒤 비교한다. PDF에서 뽑은 글은 줄바꿈과 칸 구분이 원문과 다르기 때문이다.
- 답이 여러 문서에 있으면 모두 `docs`에 넣었다(예: E30의 10km는 MAN-DS-001, QIR-2025-044, MTG-20260119). recall@k는 `need_all`이 거짓이면 `docs` 중 하나라도 상위 k건에 들면 맞은 것으로 센다.
- 스캔 질문(E47, E48)의 답은 다른 문서에 없다(테스트가 확인한다). 글을 뽑지 못하면 답할 수 없다.
- 답 없음 질문은 관련 문서가 검색되도록 만들었다. 예: E55(QX64 금형 온도)는 QX64를 다룬 문서 두 건과 QX48 조건이 검색된다.

## 6. 쓰지 않은 것

- 실제 사내 문서, 실제 회사, 실제 사람. 사람 이름은 흔한 이름으로 지어냈다.
- 주소: 오염 문서의 외부 주소는 예약 도메인(example.com)만 쓴다. 테스트가 확인한다.
- 외부 서비스 이름, API 키, 사내 주소, 사내 모델 이름.

## 8. 다시 만드는 방법

```
cd 학습자료
python tools/make_corpus.py      # 작업/코퍼스_원본/ → corpus/*.pdf, *.html, corpus_목록.csv
python tools/check_corpus.py     # 일관성 검사. "문제 없음"이 나와야 한다
python -m pytest tests/test_corpus.py -q
```

Markdown 문서를 고치면 `make_corpus.py`를 다시 실행해 목록을 갱신한다. 문서의 문장을 고치면 평가셋의 `evidence`가 깨질 수 있으므로 검사를 다시 돌린다.

## 9. 확인하지 못한 것과 사용자에게 확인할 것

- 회사 층의 질문을 모델이 정말 검색 없이 답하지 못하는지는 LLM API로 확인하지 않았다(이번 작업은 API를 부르지 않음). 7장이나 9장의 첫 실행에서 "검색 없이 답하기" 결과로 확인한다.
- 회사 이름을 두지 않았다. 이름이 있어야 문장이 자연스러운 곳은 "우리 회사"로 썼다. 이름이 필요하면 정한다.
- 사람 이름(가상) 8명을 회의록과 QIR에 썼다. 10장의 지식 그래프에서 사람과 부서의 관계로 쓸 수 있다. 실명처럼 보이는 것이 문제라면 직함으로 바꾼다.
- 오염 문서 목록을 `노트북/data/README.md`에 적었다. 15장 실습에서 학습자가 미리 보지 않게 하려면 README에서 빼고 이 문서에만 둔다.
- 평가셋의 크기(62개)는 9장 예제의 API 호출 횟수(장마다 30회 안팎)보다 크다. 9장에서는 유형별로 골라 쓰거나, 검색 평가(API를 부르지 않음)에만 전체를 쓰고 답 채점은 일부만 쓴다.
