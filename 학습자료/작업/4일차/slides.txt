   # ETCH 라인 ESC 위키 · 정리 규칙
   읽는 사람은 라인 리더입니다. 리더가 「무엇을 정해야 하고, 근거는 무엇인지」를 빨리 찾게 정리합니다.
   ## 폴더
   - 원본/ : 받은 문서 그대로입니다. 읽기만 하고 고치거나 지우거나 옮기지 않습니다.
   - wiki/ : 정리 노트입니다. index.md(목록과 한 줄 설명) · log.md(작업 기록)를 함께 고칩니다.
   ## 페이지 종류
   - 설비(호기 하나) · 주제(기준 · 절차 하나) · 이슈(불량 유형 하나) · 결정(리더가 정할 일 하나)
   ## 쓰는 규칙
   1. 원본은 고치지 않습니다.
   2. 사실을 적은 문장마다 끝에 출처 [문서번호] 를 붙입니다.
   3. 문서끼리 숫자나 기준이 다르면 한쪽으로 정하지 않습니다.

        [검토 필요] 를 붙이고 양쪽 값과 출처를 모두 적습니다.
   4. 원본에서 확인하지 못한 내용은 [미확인] 을 붙입니다. 추측으로 채우지 않습니다.
   5. 페이지끼리는 [[페이지 이름]] 으로 잇습니다.
   6. 새 원본이 들어오면 관련 페이지를 모두 찾아 고치고, 무엇이 바뀌었는지 log.md 에 적습니다.

LLM Wiki 와 온톨로지

온톨로지.txt · 개체 다섯과 관계 여섯

day04-wiki/온톨로지.txt 를 줄인 것입니다. 사람이 먼저 정하고, AI 는 이 틀대로만 관계를 뽑습니다

온톨로지.txt

개체 종류 다섯

- 설비 : 호기 하나. 예) ETCH-04

- 작업 : 공정 · 정비 작업 하나. 예) 예방정비(PM), ESC 교체, 리크 체크

- 불량 : 불량 · 이상 유형 하나. 예) 척킹 불량, ESC 온도 드리프트

- 조치 : 원인을 없애거나 재발을 막으려고 한 일 하나. 예) 표면 세정 및 배면압 재교정

- 문서 : 원본/ 의 문서 한 건. 예) QIR-2026-0712

관계 여섯 (주어 종류 -관계-> 대상 종류)

- 설비 -겪었다-> 불량   - 불량 -원인은-> (원인 단어, 문서에 적힌 그대로)

- 불량 -조치했다-> 조치  - 작업 -적용된다-> 설비

- 문서 -근거다-> 조치 또는 작업 - 문서 -개정했다-> 문서 (같은 문서번호의 새 판본이 옛 판본을)

적는 규칙

- 관계 한 줄은 「주어, 관계, 대상, 출처」 네 칸입니다. 출처는 문서번호입니다.

- 위 여섯 관계 말고는 만들지 않습니다. 원본에 없는 관계는 만들지 않습니다.

# 2. 원래 질문과 재작성 검색어 3개를 벡터·키워드로 검색해 RRF 로 합칩니다
def rewrite_search(q, k=10):

       """질문을 받아 재작성 검색어까지 써서 문서 k건을 순위대로 돌려줍니다."""
       # 빈 줄을 빼고 앞 기호를 떼어 3개만 씁니다
       rewrites = [line.strip('-· ').strip() for line in
llm(REWRITE.format(q=q)).splitlines() if line.strip()][:3]
       lists = [vec_rank(q), bm_rank(q)]
       for rewritten in rewrites:

              lists += [vec_rank(rewritten), bm_rank(rewritten)]
       return to_docs(rrf(lists), k)
