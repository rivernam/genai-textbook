## 학습 목표

1. 코딩 에이전트가 채팅과 무엇이 다른지 작업 폴더, 도구, 하네스로 설명하고, 한 줄 요청에도 입력 토큰이 수만 개 드는 이유를 설명할 수 있습니다.
2. 코딩 에이전트의 컨텍스트가 무엇으로 채워지는지 설명하고, 컨텍스트 엔지니어링이 무엇을 정하는 일인지 설명할 수 있습니다.
3. 규칙 파일과 Skill이 컨텍스트에 들어가는 시점의 차이를 설명하고, 지시를 어디에 둘지 고를 수 있습니다.
4. 서브에이전트가 메인 컨텍스트를 줄이는 원리를 설명하고, 일을 나누면 전체 토큰이 늘어날 수도 줄어들 수도 있다는 것을 계산으로 보일 수 있습니다.
5. 규칙 파일의 지시, 권한 규칙, 훅이 각각 무엇을 막고 무엇을 막지 못하는지 설명할 수 있습니다.

## 개념 확인 실습

- **실습 14-1 차단 훅 작성**: PreToolUse 훅의 판단 함수 `guard(event)`를 작성하고, 도구 요청 6건 가운데 어느 것이 막힐지 먼저 예측한다. 스크립트 안에서 파일을 지우는 명령은 문자열 검사로 막지 못한다는 것을 확인한다. API 없음.
- **실습 14-2 나누면 토큰이 줄어드는가**: 요청마다 기본 묶음과 앞 단계 도구 결과를 다시 보낸다는 모델로, 3단계와 24단계 일을 혼자 할 때와 서브에이전트 셋으로 나눌 때 보낸 입력의 합을 계산한다. API 없음.

## 사용자에게 확인할 것

1. 용어집의 "subagent" 행을 "서브에이전트"로 바꿨다(강의와 현업 표기). 다른 장에서 subagent로 쓴 곳은 없다.
2. 예제 14-1은 Claude Code가 설치되고 로그인된 PC에서만 실행된다. 사내 API만 쓰는 동료는 이 예제를 건너뛴다(셀이 안내문을 출력한다). 동료가 사내에서 Claude Code를 쓸 수 있는지에 따라 예제를 유지할지 정한다.
3. 강의 8일차 파트 3의 "에이전트가 맞는 과제의 세 조건"은 13장으로, "공유 범위와 공유 전 점검"은 15장으로 넘겼다.
4. 화면 조작(권한 프롬프트 선택, Shift+Tab, /context 화면)은 실행할 수 없어 개념과 명령 이름만 쓰고, 실행 결과처럼 싣지 않았다.
