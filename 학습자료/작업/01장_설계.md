## 학습 목표

1. LLM이 응답을 만드는 과정을 "토큰으로 나누기, 다음 토큰의 확률 계산, 하나 고르기, 이어 붙이기"의 반복으로 설명할 수 있습니다. 이 과정에 사실을 찾아보는 단계가 없다는 것도 설명할 수 있습니다.
2. 토크나이저가 BPE로 어휘를 만드는 방법을 설명하고, 같은 뜻의 한국어 문장이 영어보다 토큰이 많이 드는 이유를 설명할 수 있습니다.
3. 모델이 어휘 전체에 대한 점수(logit)를 내고 softmax로 확률 분포를 만드는 과정을 설명할 수 있습니다.
4. 같은 질문에 응답이 매번 다른 이유를 샘플링으로 설명하고, temperature와 top-p가 확률 분포를 어떻게 바꾸는지 계산으로 보일 수 있습니다.

## 확인할 사실 (원고를 쓰기 전에 공식 문서나 논문으로)

1. Anthropic API의 현행 모델이 `temperature`를 받는지. 2일차 p.63은 "최신 SDK에 없음, 넣으면 TypeError"라고 적었다. 모델별 제약인지 SDK 제약인지 확인한다.
2. OpenAI 호환 API(사내)의 `temperature`, `top_p`, `logprobs` 지원. 서버 구현마다 다르므로 "지원 여부는 서버에 따라 다르다"로 쓸지 판단한다.
3. BPE의 출처(Sennrich 외 2016)와 바이트 단위 BPE(GPT-2, Radford 외 2019). Qwen2.5 토크나이저가 바이트 단위 BPE인지.
4. Claude 토크나이저가 공개되어 있지 않다는 점. 토큰 수는 API의 토큰 세기 기능으로만 알 수 있다는 점.
5. temperature 0에서도 응답이 달라질 수 있는 원인(병렬 계산의 비결정성, 배치 구성). 출처를 찾고, 확인되지 않으면 "같지 않을 수 있다"는 관찰만 쓴다.
6. nucleus sampling(top-p)의 출처(Holtzman 외 2020). 트랜스포머와 어텐션(Vaswani 외 2017).

## 사실 확인 결과 (2026-11-27)

1. **Anthropic의 temperature**: 슬라이드 p.63의 "넣으면 TypeError"는 현재 Python SDK에 맞다. 로컬 SDK 2.1.0의 `messages.create()`에는 `temperature`, `top_p`, `top_k`가 없다. 어느 버전부터 없어졌는지는 안내 문서마다 표기가 달라(1.x, 2.0.0) 원고에는 "현재 Python SDK(2.x)"로만 쓴다. API 버전 2023-06-01에서 Opus 4.7 이후 모델은 기본값이 아닌 값을 거부한다(검토 반영 2026-11-27). API 쪽은 Claude Opus 4.7 이후 모델이 이 값을 넣으면 400 오류를 낸다. Claude Sonnet 5.5와 Haiku 5.5는 기본값이 아닌 값을 거부한다. API 버전 2026-10-21부터는 모든 모델에서 세 값을 거부한다. 공식 이전 안내는 "temperature 0은 이전 모델에서도 같은 출력을 보장하지 않았다"고 적는다. 출처: Claude API 문서의 모델 이전 안내와 API 버전 2026-10-21 이전 안내(platform.claude.com/docs/en/api/migration-2026-10-21). → 원고: "Claude 최신 모델은 temperature를 설정할 수 없다. 응답의 다양성과 일관성은 프롬프트와 출력 형식으로 조절한다."
2. **OpenAI 호환 API**: OpenAI Chat Completions는 `temperature`, `top_p`, `logprobs`, `top_logprobs`를 받는다(OpenAI API 참조, logprobs 쿡북). 사내 서버의 지원 범위는 확인할 수 없으므로 "OpenAI 호환 서버는 대개 temperature를 받지만, 지원 범위는 서버마다 다르다"로 쓴다.
3. **BPE**: Sennrich, Haddow, Birch, "Neural Machine Translation of Rare Words with Subword Units", ACL 2016. 바이트 단위 BPE: Radford 외, "Language Models are Unsupervised Multitask Learners"(GPT-2), 2019. Qwen2.5 토크나이저는 `tokenizer.json`에서 model type BPE, pre_tokenizer에 ByteLevel이 있고, 숫자는 `\p{N}` 한 글자씩 나누는 정규식으로 먼저 자른다(병합 규칙 151,387개). 그래서 숫자가 한 자리씩 나뉜다.
4. **Claude 토크나이저**: 공개되어 있지 않다. 토큰 수는 API의 토큰 세기 기능(`count_tokens`)으로 센다. Opus 4.7부터 토크나이저가 바뀌어 같은 글의 토큰 수가 1~1.35배로 늘었다는 공식 안내가 있다(모델마다 토크나이저가 다르다는 예로 쓸 수 있다).
5. **temperature 0에서도 응답이 다른 이유**: Horace He, Thinking Machines Lab, "Defeating Nondeterminism in LLM Inference"(2025-09). GPU 연산 하나하나는 대개 결정적이지만, 서버가 여러 요청을 묶어(배치) 계산할 때 배치 크기에 따라 계산 순서가 달라져 부동소수점 결과가 조금씩 바뀐다(batch invariance가 없음). → 원고: "서버는 여러 사람의 요청을 묶어 계산하는데, 묶음의 크기에 따라 계산 순서가 달라지고 소수점 아래 결과가 조금 바뀐다. 1위와 2위의 확률이 비슷한 자리에서 이 차이로 고른 토큰이 바뀌면 그 뒤 전체가 달라진다."
6. **출처**: top-p는 Holtzman 외, "The Curious Case of Neural Text Degeneration", ICLR 2020. 트랜스포머와 어텐션은 Vaswani 외, "Attention Is All You Need", NeurIPS 2017.
