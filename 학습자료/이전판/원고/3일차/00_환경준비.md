# 실습 환경 준비

3일차는 2일차와 같은 방식으로 실행합니다. 2일차 "실습 환경 준비"에서 API 키와 임베딩 모델을 준비했다면 패키지 몇 개만 더 설치하면 됩니다.

## 준비물 {추가}

| 준비물 | 설명 |
| --- | --- |
| 2일차에 준비한 것 | Python, Jupyter, `노트북` 폴더, API 접근 정보, 임베딩 모델(`HF_ENDPOINT` 설정 포함) |
| `data/3일차` 폴더 | 3일차 재료입니다. 하위 폴더와 파일은 아래 표에 있습니다 |

3일차 재료는 다음과 같습니다.

| 파일이나 폴더 | 내용 | 쓰는 곳 |
| --- | --- | --- |
| `변경_목록.csv`, `변경_문서/`, `변경_질문_6.csv` | 문서 변경 목록, 개정본과 신규 문서, 그 문서로 확인할 질문 | 파트 1 |
| `docs_raw/` | 원본 문서(PDF, DOCX, XLSX) | 파트 2 예제 |
| `청크_질문_10.csv` | 청크 크기를 비교할 질문 | 파트 2 예제 |
| `docs_raw_m2/`, `docs_raw_m2_ext/`, `실습2_질문_5.csv` | 실습용 원본 문서(PDF, DOCX, XLSX, MD), 열리지 않는 파일 2건, 질문 | 파트 2 예제와 실습 |
| `진단_질문_6.csv` | 검색 결과를 진단할 질문 | 파트 3 예제 |

3일차에는 문서 파일을 여는 패키지가 더 필요합니다. 다음 명령으로 설치합니다.

```bash
python -m pip install sentence-transformers scikit-learn pypdf python-docx openpyxl pandas
```

`pypdf`는 PDF에서 글을 뽑고, `python-docx`는 DOCX를, `openpyxl`과 `pandas`는 XLSX를 엽니다. PDF를 여는 도구로 `pdftotext`(poppler)도 쓸 수 있지만 별도로 설치해야 해서 이 교재는 `pypdf`를 기본으로 씁니다.

## 교재와 노트북 {추가}

파트마다 학습 노트북, 실습 노트북, 풀이 노트북이 있습니다. 학습 노트북은 교재의 설명과 예제 코드를 순서대로 담고 있고, 미리 실행한 결과가 들어 있습니다. 준비 셀에는 결과가 들어 있지 않으므로 연결은 직접 실행해 확인합니다.

| 파트 | 학습 노트북 | 실습 노트북 | 풀이 노트북 |
| --- | --- | --- | --- |
| 파트 1 (실습 1) | `3일차_01_벡터_DB와_RAG의_구조.ipynb` | `3일차_실습.ipynb` | `3일차_실습_풀이.ipynb` |
| 파트 2 (실습 2) | `3일차_02_문서_처리_파이프라인.ipynb` | `3일차_02_실습.ipynb` | `3일차_02_실습_풀이.ipynb` |
| 파트 3 (실습 3) | `3일차_03_첫_RAG_완성.ipynb` | `3일차_03_실습.ipynb` | `3일차_03_실습_풀이.ipynb` |

API 키와 환경 변수 설정은 2일차와 같고, 각 노트북의 "준비" 절에도 들어 있습니다. 임베딩 모델 준비(`HF_ENDPOINT`)는 노트북에 들어 있지 않으므로 2일차 "실습 환경 준비"의 "임베딩 모델 준비" 절을 따릅니다.

파트 3의 예제는 LLM API를 약 40회 호출하므로 API 요금이 듭니다. 파트 1과 2의 예제는 LLM API를 호출하지 않고 임베딩 모델만 PC에서 실행합니다. 노트북의 "준비 (2)" 셀 끝에 있는 연결 확인만 API를 한 번 호출합니다. API를 설정하지 않아 이 확인이 실패해도 파트 1과 2의 예제는 계속 실행할 수 있습니다.

## 영어 전용 모델 내려받기 {추가}

파트 1의 예제 1-3은 임베딩 모델 하나를 더 내려받습니다(`sentence-transformers/all-MiniLM-L6-v2`, 약 90MB). 영어로 학습한 모델이 한국어 문서를 얼마나 찾는지 비교하는 데 씁니다. 이 예제는 `embed.load()`를 거치지 않고 모델을 직접 불러오므로 주소를 묻지 않습니다. 내려받는 주소는 환경 변수 `HF_ENDPOINT`를 따르고, 설정하지 않았으면 `huggingface.co`에서 받으려 합니다. 2일차에 주소를 환경 변수로 설정하지 않고 셀에서 입력했다면, `setx HF_ENDPOINT`로 설정하고 Jupyter를 다시 시작한 뒤 실행합니다. 사내 프록시에 이 모델이 없어 내려받지 못하면 예제가 "건너뜁니다"를 출력하고 끝납니다. 다른 예제와 실습에는 영향이 없습니다.

## 준비 셀이 만들어 두는 이름 {추가}

3일차 노트북의 준비 셀은 모든 일자에 공통인 이름(`llm`, `os`, `json`, `time`, `pd`, `ThreadPoolExecutor`)과 아래 표의 이름을 정의합니다. 2일차의 `SYSTEM`, `PRICE`, `cost_usd()`는 정의하지 않습니다. `DATA`는 2일차와 이름이 같지만 3일차 재료 폴더를 가리킵니다.

| 이름 | 내용 |
| --- | --- |
| `np` | numpy입니다 |
| `embed` | 임베딩 함수가 든 모듈(`embed.py`)입니다. 2일차 파트 3에서 썼습니다 |
| `DATA` | 3일차 재료 폴더의 경로(`data/3일차`)입니다 |
| `CORPUS` | 문서 253건이 든 폴더의 경로(`data/2일차/corpus`)입니다 |
| `OUT` | 예제가 만드는 파일을 두는 폴더(`out`)입니다. 준비 셀이 만들어 둡니다 |
