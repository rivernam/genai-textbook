## 3. 학습 목표 (제안)

이 파트를 마치면 다음을 할 수 있다.

1. 검색 결과 청크를 프롬프트에 넣어 응답과 출처를 받고, 문서 없이 물은 응답과 비교해 달라진 점을 말한다.
2. RAG 프롬프트를 네 요소(역할 지정, 검색 결과, 출력 규칙, 근거 없음 규칙)로 구성하고, 근거 없음 규칙을 뺐을 때 생기는 일을 보인다.
3. 출처가 안정적으로 붙으려면 검색 결과의 청크마다 문서번호를 붙이는 것과 출력 규칙에서 요구하는 것이 모두 필요하다는 것을 실행해 확인한다.
4. RAG가 오류 없이 틀리는 세 경우(관련 없는 문서가 상위를 채움, 버전 충돌, 절이 문서의 맥락을 잃음)를 증상으로 알아보고, 각각의 대책을 적용한다.
5. 답이 이상할 때 검색 결과부터 확인하는 진단 함수를 작성하고, 점수만으로는 답이 있는 질문과 없는 질문을 가를 수 없다는 점을 설명한다.
6. 새 문서 묶음으로 RAG를 구성해 질문을 진단하고, 구판이 섞였을 때 고친다.

## 4. 고칠 내용

1. **"프롬프트로 고쳐진 실패는 하나도 없었다" (p.305, 318).** 이 문장은 지나치다. 원본의 비교(p.253)에서 같은 검색 결과를 발췌 꼬리표에 버전 표기를 붙여 보냈을 때는 모델이 v2.0의 값(8.0 Torr)을 골랐고, 버전 표기를 지웠을 때는 8.0과 6.0을 둘 다 적었다. 검색이 구판을 가려내지 못해도, 프롬프트에 넣는 청크에 버전을 표시하면 모델이 현행 값을 고를 수 있다는 뜻이다. 또 부록의 프롬프트 템플릿(p.315)에는 "같은 문서의 여러 판이 있으면 버전이 높은 것을 따른다"는 규칙이 들어 있어, 본문의 주장과 어긋난다. 정확한 구분은 이렇다. 규칙 문장을 고치는 것은 검색이 가져오지 못한 정보를 만들어 내지 못한다(실패 1, 3). 검색 결과에 있는 정보를 모델이 구분하게 돕는 청크 표시(버전 표기)는 프롬프트의 일이고, 구판을 인덱스에서 빼는 것이 더 확실하다(실패 2). 이 구분을 실행 결과로 확인한다(이미 ① 버전 표기 있음, ② 없음은 원본에 있다. 여기에 ③ 버전 표기와 "버전이 높은 것을 따른다" 규칙을 함께, ④ 구판을 뺀 경우를 더해 같은 질문에 응답이 어떻게 다른지 나란히 본다. 응답은 실행마다 조금 다르므로 3회씩 측정해 일치하는 정도를 적는다).
2. **"실패 1 노이즈" (p.241–248).** "노이즈"는 파트 2에서 "본문이 아닌 반복 줄"로 정의한 말이다. 파트 3의 실패 1은 반복 줄이 아니라 회의록처럼 관련 없는 문서가 검색 결과 상위를 채우는 것이어서 같은 낱말이 두 뜻으로 쓰인다. "관련 없는 문서가 상위를 채움"으로 이름을 바꾸고, 대책 네 가지(질문 구체화, 메타데이터 필터링, 하이브리드 검색, 리랭킹) 가운데 하이브리드와 리랭킹은 4일차로 넘긴다는 것만 적는다.
3. **회의록을 제외해도 "근거 없음" 그대로 (p.248).** 원본은 회의록을 제외한 검색에서 점수가 0.857~0.855로 거의 같고 응답은 "근거 없음"이라고 쓴다. 이 질문("최근 에치 장비들에서 있었던 센서 관련 품질 이슈를 정리해 주세요")에는 해당 문서가 여러 건이어서 질문을 구체화(호기와 현상을 명시)해야 한다는 결론이 더 정확하다. 필터링은 후보 유형을 줄일 뿐 질문의 모호함을 없애지 못한다는 점을 한 문장으로 쓴다.
4. **진단 지표의 한계 (p.278–282).** 진단 함수는 문자열 비교로 "출처 표기"(정규식 `\[[A-Z]+-`)와 "근거 없음"(고정 문구 포함 여부)을 센다. 모델이 문구를 조금 바꿔 쓰면 못 찾는다. 이 한계를 적고, 응답이 인용한 문서번호가 검색 결과 안에 있는지 확인하는 열을 더한다. 검색 결과에 없는 문서번호를 인용했다면 지어낸 출처다(원본 p.283의 "인용된 문장을 검색 결과에서 눈으로 찾는다"를 코드로 옮긴 것).
5. **구판과 개정판 동점의 이유 (p.249–251).** 원본은 "구판은 숫자 몇 개만 다르고 벡터는 0.999"라고 쓴다. 2일차 파트 3의 문서 단위 결과(0.913과 0.912)와 합쳐서, 임베딩 모델은 숫자의 차이로 문서의 신구를 판단하지 못한다는 점을 한 문단으로 정리한다.
6. **점수 해석 (p.243).** "벌어짐"이라는 말은 쓰지 않고 "1위와 4위의 점수 차"로 쓴다. 점수의 절대값(없는 호기 0.914가 정상 0.840보다 높다)과 점수 차로 답이 있는 질문과 없는 질문을 가를 수 없다는 점은 2일차 파트 3의 결과(정답이 없는 질문의 1위 점수가 0.824, 0.849)와 같은 이야기이므로 서로 가리킨다.
7. **API 호출 방식.** 원본은 `anthropic` 클라이언트를 직접 쓰고, `output_config={'effort': 'low'}`, `stop_reason == 'refusal'` 처리, 응답의 글자 조각만 이어 붙이는 코드를 셀 안에 둔다. 이 교재는 `llm.ask()`로 호출한다. 키의 앞 7글자를 출력하는 셀(p.204–205)은 키 일부도 출력하지 않는다는 규칙(`00_환경준비.md`)에 어긋나므로 싣지 않는다. `ThinkingBlock`에 `text`가 없다는 오류(미션 3 재료 p.115)는 `llm.py`가 처리하므로 해당하지 않는다.
8. **1일차 "네 층 프롬프트" (p.230).** 1일차 교재의 용어에 맞춰 "프롬프트의 네 요소(역할 지정, 맥락, 형식, 제약)"로 쓴다. RAG에서는 맥락을 검색이 채우고(검색 결과), 형식이 출력 규칙(문장마다 문서번호), 제약이 근거 없음 규칙에 해당한다. "층"은 쓰지 않는다(작성규칙).
9. **유형 이름.** 원본의 "대조군"은 2일차 파트 3의 용어(근거 없이 보낸 응답)에 맞춰 같은 이름을 쓴다. "발췌"는 프롬프트에 넣는 청크를 가리키지만 "발췌 칸", "발췌만 근거로"에서 낱말이 흩어지므로 "검색 결과"(검색이 가져온 청크)로 통일한다. 색인 → 인덱스. 꼬리표 → 메타데이터. "제목 접두 색인" → "제목을 붙여 임베딩한 인덱스"(파트 2의 접두어 `query: `와 구분된다).
10. **부록의 "심어 둔 장치 (강사용)" (p.320).** 정답 문서와 충돌의 위치를 정리한 표다. 교재에서는 숨길 이유가 없으므로 "데이터 사전"(p.319)과 합쳐 코퍼스 설명으로 싣는다.

## 5. 추가할 내용

1. **이 파트에서 만드는 것.** 입력(질문 하나)과 출력(검색 결과 청크 4건, 출처가 붙은 응답)의 예를 첫 절에 보인다.
2. **출처 표기 실험.** 원본은 "둘 다 있어야 한다"를 말로만 설명한다(p.237, 퀴즈 13번). 같은 질문을 ① 규칙만, ② 청크의 문서번호 표시만, ③ 둘 다로 보내 출처가 붙는 모양을 비교한다.
3. **인용한 문서번호 검증.** 진단 함수의 열을 하나 더한다(4절 4번).
4. **제목을 붙이는 효과를 측정.** 원인 절 하나가 아니라 2절의 마지막에서 둘째 행의 사례를 함께 보이고, 제목을 붙이지 않은 인덱스와 붙인 인덱스에서 2일차 질문 20개의 recall@1을 비교한다. 이 측정은 아직 실행하지 않았다.
5. **운영 항목.** 문서 범위, 갱신 주기, 접근 권한, 오답 신고의 네 가지를 짧은 목록으로 싣고, 접근 권한과 갱신 운영은 5일차에서 다룬다고 쓴다(p.286, 29).

## 6. 삭제할 내용

- p.199–207: 파트 도입, 환경 준비 셀(키, 클라이언트), 모델 고르는 기준은 2일차 파트 1과 `00_환경준비.md`에서 다룬 내용이다.
- 조립 셀을 여섯 쪽에 걸쳐 보이는 설명 방식(p.210–217): 코드는 예제마다 필요한 만큼으로 나눠 싣는다(예제 3-1).
- "내보내기 전 확인"(p.225), "답을 세 등급으로"(p.285, 이미지만 있음), "여러 단계를 잇는 흐름"(p.287): 확인 항목은 p.283의 네 줄로 합치고 나머지는 삭제한다.
- Wrap-Up, 이해도 설문, 다음 일차 예고, 부록의 오류 모음·치트시트(p.303–325): 요점은 핵심 정리와 자가점검에 반영하고 운영 안내는 삭제한다. RAG 구성 요소 지도(p.304)는 "이 교재의 예제가 인덱싱, 검색, 생성 중 어느 칸인가"를 보이는 표로 핵심 정리에 싣는다.
- 확장 미션, 제출물, 체크포인트: 운영 안내다.
