# 파트 3. 코딩 에이전트 시작하기

<!-- 실행 위치: 노트북/코딩도구_실습_1일차 -->

파트 2까지는 프롬프트에 재료를 붙여 넣고 응답을 글로 받았습니다. 재료가 폴더에 여러 파일로 쌓여 있고 결과도 파일로 남겨야 하는 일은 이 방식으로 하기 번거롭습니다. 이 파트에서는 그런 일을 [[코딩 에이전트]]에 맡깁니다. 코드는 작성하지 않습니다. 회의록 10건이 든 폴더를 맡겨 회의 요약표와 주간 보고 초안을 파일로 받고, 그 결과가 맞는지 확인합니다.

이 파트를 마치면 다음을 할 수 있습니다.

1. 채팅과 코딩 에이전트의 차이를 작업 폴더, 도구, 에이전트 루프로 설명하고, 일을 어느 쪽에 맡길지 고릅니다.
2. 권한 요청에서 무엇이 바뀌는지 읽고 허용하거나 거부합니다. 중지, 되돌리기, 새 세션을 상황에 맞게 사용합니다.
3. 폴더의 자료로 결과 파일을 만드는 작업을 목적, 입력, 출력, 제약, 끝난 뒤 보고할 것을 갖춘 요청으로 작성합니다.
4. 결과 파일을 원문과 대조하고 검사 스크립트로 판정합니다. 요청 한 줄을 바꿔 결과가 어떻게 달라지는지 숫자로 비교합니다.

이 파트에는 학습 노트북이 없습니다. 예제와 실습은 `노트북/코딩도구_실습_1일차` 폴더에서 Claude Code나 opencode로 합니다. 교재에 실은 코딩 에이전트의 실행 결과는 Claude Code가 작업의 일부를 맡기려고 따로 실행하는 에이전트(subagent)에 요청 글을 그대로 보내 얻은 것입니다. 사람이 터미널에서 새 세션을 열어 보낸 것과 같은 모델이 같은 도구로 실행했지만, 화면과 권한 요청은 거치지 않았습니다(세션은 "사람이 개입하는 네 가지" 절에서 설명합니다). 응답과 결과 파일은 실행할 때마다 조금씩 다릅니다(실행일 2026-11-23).

## 이 파트에서 만드는 것 {추가}

:::요점
형식이 서로 다른 회의록 10건이 입력이고, 회의 하나를 한 행으로 정리한 회의 요약표와 양식에 맞춘 주간 보고 초안이 출력입니다.
:::

입력은 장비팀의 8월 3주차 회의록 10건입니다. 모두 지어낸 가상 자료입니다. 형식이 회의마다 다릅니다. 안건과 액션이 나뉜 회의록, 메모, 표, 받아쓰기, 메일이 섞여 있습니다. 담당이나 기한이 적혀 있지 않은 회의도 있습니다. 아래는 그 가운데 두 건입니다.

```
품질팀 협의 (스크랩 사유 코드)
2026-08-19 15:00 / 장비팀 이OO, 김OO / 품질팀 2명

내용
- 지난달 회신한 스크랩 사유 코드 정리본을 두고 품질팀이 비슷한 코드 3개를 하나로 합치자고 제안함.
- 장비팀도 동의함. 합친 코드표로 개정안을 만들어 품질팀에 보내기로 함.
- 개정안 회신 기한: 8/26(수)
- 개정안을 누가 만들지는 정하지 못함. 다음 주간회의에서 정하기로 함.
```

```
[5호기 알람 E-201 대응 회의 · 받아쓰기] 2026-08-19 수요일 10:30

(최파트장) 캘리 장비 순번 정리됐나요?
(정OO) 보전팀이랑 얘기했고요, 3호기 쪽 일정이 끝나는 금요일 오후에 5호기로 옮기기로 했습니다.
(최파트장) 캘리는 누가 하죠?
(보전팀 문OO) 저희가 금요일 오후에 바로 하겠습니다.
```

출력은 두 가지입니다. 첫째는 회의 요약표(`결과/회의요약표.md`)입니다. 회의 하나가 한 행이고, 열은 날짜, 주제, 결정, 액션, 담당, 기한입니다. 원문에 없는 칸에는 "미기재"라고 적습니다.

| 날짜 | 주제 | 결정 | 액션 | 담당 | 기한 |
| --- | --- | --- | --- | --- | --- |
| 2026-08-19 | 품질팀 협의 (스크랩 사유 코드) | 비슷한 스크랩 사유 코드 3개를 하나로 합친다 | 합친 코드표로 개정안을 만들어 품질팀에 회신 | 미기재 | 2026-08-26 |
| 2026-08-20 | 신입 교육 계획 회의 | 야간조에 들어가기 전에 설비 기본 조작 실습을 2회 더 한다 | 1) 실습 일정표 작성 2) 실습 1회차 진행 | 1) 정OO 2) 정OO | 1) 2026-08-24 2) 2026-08-26 |

둘째는 주간 보고 초안(`결과/주간보고_초안.md`)입니다. 정해진 양식(`양식/주간보고_양식.txt`)의 다섯 항목을 순서대로 채웁니다. 이번 주 요약, 주요 결정 사항, 다음 주까지 할 일, 확인이 필요한 것, 참고한 회의록입니다.

실습 폴더의 구성은 다음과 같습니다. 코딩 에이전트에는 `작업폴더`만 열어 줍니다.

```
코딩도구_실습_1일차/
  작업폴더/            코딩 에이전트에 열어 주는 폴더
    회의록/            회의록 10건
    양식/              주간보고_양식.txt
    결과/              결과 파일이 저장되는 곳
  요청_글/             예제와 실습에서 보낼 요청
  check.py             회의 요약표를 검사하는 스크립트
  풀이/                요청 예시와 결과 예시
```

## 채팅과 코딩 에이전트 {원본 p.216-218, 226-231}

:::요점
코딩 에이전트는 내 컴퓨터의 작업 폴더에서 파일을 직접 읽고 씁니다. 그리고 작업이 끝날 때까지 도구를 골라 실행하고 결과를 확인하는 일을 되풀이합니다.
:::

파트 1에서 [[에이전트]]를 다음 행동과 도구 사용을 LLM이 스스로 정하는 시스템이라고 했습니다. 코딩 에이전트는 사용자 컴퓨터의 폴더에서 일하는 에이전트이고, Claude Code와 opencode가 여기에 해당합니다. 이름은 코딩이지만 파일을 읽고 정리하는 문서 작업에도 쓸 수 있습니다. 채팅과 다른 점은 다음 세 가지 개념으로 설명할 수 있습니다.

- **[[작업 폴더]]**는 코딩 에이전트를 시작한 폴더입니다. 코딩 에이전트는 기본으로 이 폴더의 파일을 읽고, 만들고, 고칩니다. 채팅은 사용자가 붙여 넣거나 첨부한 글만 읽습니다.
- **[[도구]]**(tool)는 에이전트가 글을 생성하는 것 외의 일을 하는 데 쓰는 기능입니다. 코딩 에이전트의 도구는 파일 읽기, 파일 쓰기, 명령 실행입니다. 어떤 도구를 어떤 순서로 쓸지는 모델이 정합니다.
- **[[에이전트 루프]]**(agent loop)는 자료를 읽고, 도구를 실행하고, 결과를 확인하는 일을 작업이 끝날 때까지 되풀이하는 방식입니다. 예제 3-1의 채팅처럼 도구를 쓰지 않는 채팅은 요청 하나에 응답 하나로 끝납니다.

채팅 서비스 가운데에는 파일을 첨부받고 파일을 만들어 주는 것도 있습니다. 그래서 "채팅은 글로 답하고 코딩 에이전트는 파일을 만든다"는 구분은 제품에 따라 맞지 않습니다. 세 개념 가운데 제품이 바뀌어도 남는 차이는 작업 폴더와 에이전트 루프입니다. 코딩 에이전트는 내 컴퓨터의 작업 폴더에서 일하고, 그 폴더의 파일을 읽고 쓰며 끝날 때까지 도구를 골라 실행하는 일을 되풀이합니다.

:::예제 3-1 같은 일을 채팅과 코딩 에이전트에 맡기기
채팅 쪽에는 회의록 한 건을 붙여 넣고, 나머지 9건도 읽어 파일로 저장해 달라고 요청합니다(`요청_글/예제3-1_채팅에_붙여넣기.txt`). 파트 2의 `llm.Chat`으로 기본 모델에 보냈습니다.

```
아래 회의록을 표 하나로 정리해 주세요. 열은 날짜, 주제, 결정, 액션, 담당, 기한입니다. 원문에 없는 칸은 "미기재"로 적습니다.
이 회의록 말고도 같은 폴더에 회의록이 9건 더 있는데, 그것도 모두 읽어서 표 하나로 합쳐 파일로 저장해 줄 수 있나요?

(이 아래에 회의록/0817_장비팀_주간회의.txt 의 내용을 붙여 넣습니다)
```

:::결과
```
## 나머지 9건 합치기

이 대화에서는 사용자 폴더에 접근할 수 없고 파일을 만들어 저장할 수도 없어서, 나머지 회의록을 직접 읽고 파일로 저장하는 것은 어렵습니다.

대신 아래 방법은 가능합니다.
- 나머지 9건의 본문을 대화창에 붙여넣거나 파일로 첨부해 주시면, 이 건과 합쳐 같은 열 구성의 표 하나로 만들어 드립니다.
- 파일 형태가 필요하시면 CSV 형식 텍스트로 드리겠습니다. 이를 메모장에 붙여넣어 `.csv`로 저장하면 엑셀에서 바로 열 수 있습니다.
```
:::

모델은 붙여 넣은 한 건을 안건별 세 행의 표로 정리했습니다. 위에는 그 표와 응답의 마지막 한 줄을 빼고 실었습니다. 나머지 9건은 읽지 못했고 파일도 만들지 못했습니다.

코딩 에이전트 쪽에는 작업 폴더를 열고 다음 요청을 보냅니다(`요청_글/예제3-1_폴더째_맡기기.txt`).

```
회의록 폴더의 회의록을 모두 읽고, 회의마다 한 행씩 날짜, 주제, 결정을 표로 정리해 결과/회의목록.md 로 저장해 주세요.
저장한 뒤 몇 개 파일을 읽었는지 한 줄로 알려 주세요.
```

:::결과
```
회의록 폴더의 파일 10개를 모두 읽고, 회의마다 한 행씩(총 10행) 정리해 결과/회의목록.md 로 저장했습니다.
```
:::

저장된 `결과/회의목록.md`의 앞부분은 다음과 같습니다.

```
| 날짜 | 주제 | 결정 | 원본 파일 |
|---|---|---|---|
| 2026-08-17 | 야간조 인수인계 회의 | 인수인계 노트를 공용 양식 하나로 통일한다(한OO가 초안을 8/21까지 공유). 2호기 챔버 압력 경보는 재발하지 않으면 따로 조치하지 않는다. | 0817_야간조_인수인계회의.txt |
| 2026-08-17 | 장비팀 주간회의(8월 3주차) | 3호기 인터락 건은 종료하고 2주 동안 재발 여부만 지켜본다. 8/24 주부터 야간조는 C조 지원 인원 1명을 더해 운영한다. | 0817_장비팀_주간회의.txt |
```
:::

코딩 에이전트는 폴더의 파일 목록을 한 번 조회하고, 회의록 10개를 읽고, 결과 파일을 한 번 썼습니다. 요청하지 않은 "원본 파일" 열을 하나 더 넣었습니다. 요청에 적지 않은 부분은 모델이 정한다는 점을 "요청 쓰는 법" 절에서 다시 다룹니다.

| 비교한 것 | 채팅 | 코딩 에이전트 |
| --- | --- | --- |
| 읽은 회의록 | 붙여 넣은 1건 | 작업 폴더의 10건 |
| 결과 | 화면의 표(1건분) | `결과/회의목록.md` 파일(10행) |
| 사람이 할 일 | 회의록 붙여 넣기. 나머지 9건을 붙여 넣고 결과를 복사해 저장하는 일이 남음 | 요청 작성, 권한 요청 확인, 결과 파일 확인 |

어느 쪽에 맡길지는 자료와 결과가 어디에 있는지로 정합니다.

- 자료가 한두 건이고 응답을 읽고 끝나는 일이면 채팅에 맡깁니다.
- 자료가 폴더에 여러 파일로 있고 결과를 파일로 남겨야 하면 코딩 에이전트에 맡깁니다.

:::주의
코딩 에이전트는 작업 폴더의 파일을 읽어 모델에 보냅니다. 파트 1의 "입력하면 안 되는 정보" 기준이 그대로 적용됩니다. 입력하면 안 되는 파일이 든 폴더는 작업 폴더로 열지 않습니다. 작업 폴더 밖의 파일을 읽을 때 묻는지는 코딩 에이전트마다 다릅니다(다음 절의 코딩 에이전트별 조작 표). opencode는 기본 설정에서 작업 폴더 밖의 파일도 묻지 않고 읽습니다.
:::

## 사람이 개입하는 네 가지 {원본 p.223, 232-239}

:::요점
파일이 바뀌기 전에는 권한 요청을 읽고, 실행 중에는 중지하고, 끝난 뒤에는 되돌리거나 새 세션에서 다시 시작합니다. 조작하는 방법은 코딩 에이전트마다 다릅니다.
:::

코딩 에이전트는 내 컴퓨터의 파일을 바꿉니다. 그래서 일을 맡기기 전에 멈추는 방법과 되돌리는 방법부터 알아 둡니다.

**[[권한 요청]]**은 코딩 에이전트가 파일을 바꾸거나 명령을 실행하기 전에 사용자에게 허용할지 묻는 것입니다. 권한 요청이 나오면 세 가지를 읽습니다.

- 어느 파일인가. 경로가 작업 폴더 안인지, 요청한 결과 파일이 맞는지 봅니다.
- 무엇이 바뀌는가. 새로 만드는 파일인지, 있던 파일의 어느 줄을 고치는지 봅니다.
- 명령이라면 어떤 명령인가. 파일을 지우거나 옮기는 명령인지 봅니다.

요청한 일과 관계없는 파일이거나 작업 폴더 밖의 경로이면 거부합니다. 처음에는 한 번만 허용하는 선택지(Claude Code의 "Yes", opencode의 "Allow once")를 고릅니다. 항상 허용하는 선택지(Claude Code의 "Yes, and don't ask again…", opencode의 "Allow always")를 고르면 같은 종류의 행동을 다시 묻지 않습니다.

어떤 행동을 묻지 않고 실행할지는 **[[권한 모드]]**라는 설정이 정합니다. 묻지 않고 파일을 고치는 모드도 있고, 코딩 에이전트에 따라서는 그 모드가 기본값입니다. 첫 요청을 보내기 전에 지금 모드가 무엇인지 확인합니다. 결과를 검증하는 방법에 익숙해지기 전에는 파일을 바꿀 때마다 묻는 모드를 씁니다.

**중지**는 실행 중인 작업을 사람이 멈추는 것입니다. 작업이 길어지거나 요청과 다른 방향으로 가면 멈춥니다. 멈추기 전에 이미 만든 파일은 그대로 남습니다.

**[[되돌리기]]**는 고른 메시지를 보내기 전의 상태로 대화와 파일을 되돌리는 기능입니다. 결과가 틀렸거나 요청을 고쳐 다시 받고 싶을 때 씁니다. Claude Code는 대화만 되돌리거나 파일만 되돌리는 선택지도 있으므로, 대화와 파일을 함께 되돌리려면 "Restore code and conversation"을 고릅니다. 되돌리기로 복원되지 않는 변경이 있습니다. Claude Code는 파일 편집 도구로 고친 파일을 추적하고, 셸 명령으로만 바뀐 파일(`rm`, `mv`, `cp`의 결과)은 추적하지 않습니다. 되돌릴 수 없으면 곤란한 폴더는 맡기기 전에 사본을 만들어 둡니다.

**[[세션]]**은 코딩 에이전트와 나누는 대화 하나입니다. 새 세션은 앞 세션의 대화를 알지 못합니다. 작업 폴더의 파일은 그대로 있으므로 새 세션에서도 읽을 수 있습니다. 주제가 바뀌면 새 세션에서 시작하고, 다음 세션에 이어 갈 내용은 파일로 남깁니다.

아래 표는 세 가지 코딩 에이전트에서 같은 일을 하는 방법입니다. 예제 3-2를 하기 전에 쓸 코딩 에이전트의 칸을 읽어 둡니다. 각 코딩 에이전트의 공식 문서에서 확인했고, 문서에서 확인하지 못한 칸은 비워 두었습니다(2026-11-23 확인. 권한 모드, 되돌리기, opencode 설정은 2026-11-26 다시 확인).

| 하는 일 | Claude Code(터미널) | Claude Code(VS Code 확장) | opencode |
| --- | --- | --- | --- |
| 시작 | 작업 폴더에서 `claude` 실행 | VS Code에서 작업 폴더를 열고 편집기 오른쪽 위의 Claude Code 아이콘 클릭 | 작업 폴더에서 `opencode` 실행 |
| 권한 모드 확인과 전환 | `Shift+Tab`으로 전환. 파일 수정과 셸 명령을 묻는 모드는 `default`(상태 표시줄에 "manual mode on") | 입력 상자 아래의 모드 표시를 클릭. 묻는 모드는 "Manual" | 기본 설정은 파일 수정과 셸 명령을 묻지 않고 실행. 묻게 하려면 설정 파일에 규칙을 적음 |
| 권한 요청의 선택지 | "Yes", "Yes, and don't ask again…", "No". `Esc`는 거부 | | "Allow once", "Allow always", "Reject" |
| 중지 | `Esc` | `Esc` | `Esc` |
| 되돌리기 | `/rewind`(별칭 `/undo`), 또는 입력란이 비었을 때 `Esc` 두 번. 메뉴에서 "Restore code and conversation"을 고름 | 메시지에 마우스를 올리면 나오는 되돌리기 단추 | `/undo`. 다시 적용은 `/redo` |
| 새 세션 | `/clear` | | `/new` |
| 이전 세션 이어 가기 | `claude --continue`, `claude --resume` | 패널 위쪽의 "Session history" 단추 | `/sessions` |

표에서 눈여겨볼 점은 세 가지입니다.

- **Claude Code의 `default` 모드에서도 작업 폴더 안의 파일 읽기는 묻지 않습니다.** 파일 수정, 읽기 전용이 아닌 셸 명령, 작업 폴더 밖의 파일을 읽는 일은 묻습니다. 그래서 Claude Code에서는 작업 폴더를 고르는 일이 곧 묻지 않고 읽어도 되는 범위를 정하는 일입니다.
- **opencode는 기본 설정에서 파일 수정과 셸 명령을 묻지 않습니다.** 작업 폴더 밖의 경로도 기본 설정에서는 묻지 않습니다. 권한 요청을 받으려면 설정 파일의 `permissions`에 규칙을 적어야 합니다. 설정 파일은 작업 폴더에 `opencode.json`으로 만듭니다. 모든 프로젝트에 적용하려면 `~/.config/opencode/opencode.json`에 적습니다.
- **되돌리기의 범위는 코딩 에이전트마다 다릅니다.** Claude Code의 문서에는 셸 명령으로만 바뀐 파일을 추적하지 않는다고 적혀 있습니다. opencode의 문서는 `/undo`가 마지막 사용자 메시지와 그 뒤의 작업을 되돌린다고만 설명하고, 셸 명령으로 바뀐 파일을 되돌리는지는 적혀 있지 않습니다.

아래는 opencode 문서의 규칙 형식에 맞춰 쓴 설정 예입니다. 파일 수정, 셸 명령, 작업 폴더 밖의 경로 접근을 할 때마다 묻게 합니다. 이 교재를 만들 때 실행해 확인하지는 못했습니다. 설정 형식은 버전에 따라 다르므로 설치한 버전의 문서를 확인합니다.

```json
{
  "permissions": [
    { "action": "edit", "resource": "*", "effect": "ask" },
    { "action": "shell", "resource": "*", "effect": "ask" },
    { "action": "external_directory", "resource": "*", "effect": "ask" }
  ]
}
```

:::예제 3-2 권한 요청, 되돌리기, 중지, 새 세션 써 보기
작업 폴더(`작업폴더`)에서 코딩 에이전트를 시작하고, 파일을 바꿀 때마다 묻는 모드인지 위 표에서 확인한 뒤 아래 순서로 합니다. opencode는 위의 설정 예를 `작업폴더/opencode.json`에 적어 두어야 1단계와 3단계에서 권한 요청이 나옵니다. 요청 글은 `요청_글` 폴더에 있습니다.

**1단계: 권한 요청 읽기.** `예제3-2_권한_요청.txt`의 글을 보냅니다. `결과/메모.txt`를 만들겠다는 권한 요청이 나오면 파일 경로와 내용을 읽고 한 번만 허용하는 선택지를 고릅니다.

```
회의록/0818_안전점검_후속회의.txt 를 읽고, 이 회의에서 정한 할 일만 골라 결과/메모.txt 에 세 줄 이하로 적어 주세요.
```

**2단계: 되돌리기.** 방금 보낸 메시지 이전으로 되돌립니다. Claude Code에서는 되돌리기 메뉴에서 "Restore code and conversation"을 고릅니다. `결과/메모.txt`가 사라졌는지 폴더에서 확인합니다.

**3단계: 중지.** `예제3-2_중지.txt`의 글을 보냅니다. 파일을 두 개쯤 허용한 뒤 중지합니다. `결과/회의별` 폴더에 그때까지 만든 파일이 남아 있는지 확인합니다.

```
회의록 폴더의 회의록마다 한 장짜리 요약 파일을 결과/회의별/ 폴더에 하나씩 따로 만들어 주세요.
```

**4단계: 새 세션.** 새 세션을 열고 `예제3-2_새_세션.txt`의 글을 보냅니다. 폴더의 파일은 알고 앞의 요청은 모른다고 답하는지 봅니다.

```
결과 폴더에 지금 어떤 파일이 있는지 보여 주세요. 그리고 이 대화 전에 내가 무엇을 부탁했는지 알고 있는지 한 줄로 답해 주세요.
```

이 예제는 화면에서 사람이 조작해야 해서 교재에 실행 결과를 싣지 못했습니다. 예제를 마치면 `결과` 폴더에 생긴 파일을 지우고 실습으로 넘어갑니다.
:::

## 요청 쓰는 법 {추가}

:::요점
코딩 에이전트에 보내는 요청에는 목적, 입력, 출력, 제약, 끝난 뒤 보고할 것을 적습니다. 적지 않은 부분은 모델이 정하고, 그 결정은 실행할 때마다 다를 수 있습니다.
:::

코딩 에이전트에 보내는 요청도 프롬프트이므로 파트 2의 다섯 요소(역할 지정, 맥락, 형식, 제약, 예시)를 그대로 쓸 수 있습니다. 다만 결과가 화면의 글이 아니라 파일이므로, 이 파트에서는 요청을 아래 다섯 요소로 나눠 씁니다. 출력은 파트 2의 형식에 해당하고, 제약은 파트 2의 제약과 같습니다.

| 요소 | 적는 내용 | 회의 요약표 요청에서 |
| --- | --- | --- |
| 목적 | 무엇을 만드는가 | 회의록을 모두 읽고 회의 요약표를 만든다 |
| 입력 | 어느 폴더, 어느 파일을 읽는가 | `회의록` 폴더의 회의록 전부 |
| 출력 | 저장할 경로, 파일 형식, 열과 행의 구성 | `결과/회의요약표.md`. 회의 하나에 한 행. 열 여섯 개의 이름과 순서 |
| 제약 | 형식의 세부 규칙, 원문에 없는 내용의 처리 | 날짜 형식, 날짜로 바꿀 말과 그대로 둘 말, 원문에 없는 칸은 "미기재" |
| 끝난 뒤 보고할 것 | 사람이 확인하는 데 쓸 숫자 | 읽은 회의록 수, "미기재" 칸 수 |

"끝난 뒤 보고할 것"은 파트 2의 다섯 요소에는 없던 요소입니다. 코딩 에이전트는 여러 파일을 읽고 쓰므로, 무엇을 몇 개 처리했는지를 숫자로 받아 두면 결과를 확인할 때 대조할 기준이 생깁니다.

:::예제 3-3 한 줄 요청과 요소를 갖춘 요청
같은 작업 폴더의 사본 두 개에 서로 다른 요청을 보냈습니다. 첫째는 한 줄 요청입니다(`요청_글/예제3-3_한_줄_요청.txt`).

```
회의록 폴더의 회의록을 표로 정리해서 결과 폴더에 저장해 주세요.
```

둘째는 위 표의 다섯 요소를 모두 적은 요청입니다. 실습 4에서 이 요청을 직접 작성하므로 여기에는 전문을 싣지 않습니다. 실습을 마친 뒤 `풀이/요약표_요청_예시.txt`와 비교합니다.

두 결과 파일을 비교하면 다음과 같습니다.

| 비교한 것 | 한 줄 요청 | 요소를 갖춘 요청 |
| --- | --- | --- |
| 파일 이름 | `결과/회의록_정리.md` | `결과/회의요약표.md` |
| 표의 수 | 3개(회의별 요약, 할 일, 확인이 필요한 것) | 1개 |
| 회의별 요약의 열 | 번호, 날짜, 회의, 참석, 논의 내용, 결정 사항, 파일 | 날짜, 주제, 결정, 액션, 담당, 기한 |
| 날짜 표기 | 8/17(월) | 2026-08-17 |
| 원문에 없는 칸 | "정하지 않음", "적혀 있지 않음" | "미기재" |
| `check.py` | 0/8(검사할 파일 이름이 다름) | 8/8 |
:::

한 줄 요청의 결과가 틀린 것은 아닙니다. 회의 10건을 모두 읽었고, 할 일 20건을 기한순으로 정리했고, 담당이나 기한이 없는 일을 따로 모았습니다. 문제는 파일 이름, 표의 수, 열, 날짜 표기, 빈칸의 표기를 모두 모델이 정했다는 점입니다. 다음에 같은 요청을 보내면 다르게 정할 수 있습니다. 결과를 받아 다음 단계에서 쓰려면 이 다섯 가지가 매번 같아야 합니다. 주간 보고 요청은 `결과/회의요약표.md`를 읽고, 검사 스크립트는 "미기재"라는 표기를 찾기 때문입니다.

요청을 쓸 때는 결과 파일을 누가, 또는 어떤 프로그램이 받아서 쓰는지를 먼저 생각하고, 받는 쪽이 기대하는 것을 요청에 적습니다.

## 결과 검증 {원본 p.240-248}

:::요점
코딩 에이전트가 끝났다고 답한 것은 결과가 맞다는 근거가 아닙니다. 개수를 세고, 원문과 대조하고, 검사 스크립트로 판정합니다.
:::

코딩 에이전트는 작업을 마치면 무엇을 했는지 응답으로 알려 줍니다. 이 응답은 모델이 생성한 글입니다. 파트 1에서 확인했듯이 모델은 근거가 없는 내용도 사실처럼 씁니다. 결과가 맞는지는 결과 파일을 직접 확인해 판정합니다. 방법은 세 가지이고, 뒤로 갈수록 준비가 더 필요합니다.

- **개수를 셉니다.** 회의록이 10건이면 요약표도 10행이어야 합니다. 응답에 적힌 숫자와 파일에서 직접 센 숫자가 같은지 봅니다.
- **원문과 대조합니다.** 행을 두세 개 골라 원문 파일을 열고 결정, 담당, 기한이 원문과 같은지 봅니다. "미기재"라고 적힌 칸은 원문에 정말 없는지 확인합니다.
- **검사 스크립트로 판정합니다.** 형식처럼 규칙으로 확인할 수 있는 것은 코드에 맡깁니다. `check.py`는 회의 요약표가 요청의 조건을 지켰는지 여덟 가지를 검사하고 "결과 N/8 통과"를 출력합니다. 모델을 부르지 않으므로 요금이 들지 않습니다.

`check.py`가 검사하는 여덟 가지는 다음과 같습니다.

1. 열이 날짜, 주제, 결정, 액션, 담당, 기한 순서다.
2. 회의 하나에 한 행으로 10행이다.
3. 날짜 열이 2026-08-17 형식이고 회의록의 날짜와 같다.
4. 기한 칸에 8/28처럼 줄여 쓴 날짜가 괄호 밖에 남아 있지 않다.
5. "다음 주 화요일"이 2026-08-25로 바뀌고 원문이 괄호에 남았다.
6. "9월 첫째 주"와 "캘리 끝날 때까지"는 날짜로 바꾸지 않았다.
7. 원문에 없는 담당(품질팀 협의)과 기한(폐액 라벨)은 "미기재"이고, 담당과 기한이 모두 적힌 회의 4건(야간조 인수인계, 레시피 A-7, 안전점검, 신입 교육)의 담당과 기한은 채웠다.
8. 표 아래에 적은 회의록 수가 10이고, "미기재" 칸 수가 표에서 센 수와 같다.

예제 3-3의 요소를 갖춘 요청으로 받은 요약표는 여덟 가지를 모두 통과했습니다. 그래도 원문 대조는 필요합니다. 그 요약표를 원문과 대조하면 코딩 에이전트가 판단해 넣은 내용이 두 군데 있습니다.

- 협력사 정기 미팅의 "베어링 점검"에 담당을 "협력사"라고 적었습니다. 원문에는 "협력사가 베어링 점검을 함께 하기로 했습니다"라고만 있고, 담당이라는 말은 없습니다.
- 장비팀 주간 마감 회의는 액션, 담당, 기한 세 칸을 "미기재"로 적어 "미기재"가 모두 5칸이었습니다. 같은 회의를 "품질팀 개정안 담당을 8/24 주간회의에서 정한다"는 액션으로 읽고 결정 칸을 "미기재"로 두면, 이 회의의 "미기재"는 결정과 담당 2칸이 되어 모두 4칸입니다(`풀이/회의요약표_예시.md`).

두 번째 경우는 어느 쪽이 맞다고 정할 수 없습니다. 원문에 "새로 정한 것은 없음"이라고 적혀 있기 때문입니다. 그래서 `check.py`는 "미기재"가 몇 칸이어야 하는지를 검사하지 않습니다. 해석이 하나뿐인 칸(품질팀 협의의 담당, 폐액 라벨 회의의 기한)과, 코딩 에이전트가 적은 수가 표에서 센 수와 같은지만 검사합니다. 검사 스크립트를 통과했다는 것은 검사한 항목이 맞다는 뜻이고, 나머지는 사람이 원문과 대조해야 합니다.

:::주의
`check.py`와 `풀이` 폴더는 작업 폴더 밖에 있습니다. 작업 폴더 안에 두면 코딩 에이전트가 검사 기준과 예시를 읽고 결과를 거기에 맞출 수 있습니다. 그러면 검사를 통과해도 요청이 좋았기 때문인지 알 수 없습니다. opencode는 기본 설정에서 작업 폴더 밖의 파일도 묻지 않고 읽습니다. opencode로 실습할 때는 앞의 설정 예처럼 `external_directory` 규칙을 `ask`나 `deny`로 적어 둡니다.
:::

요청을 고쳤을 때 결과가 어떻게 달라지는지도 숫자로 확인합니다. 주간 보고 초안을 두 가지 요청으로 받았습니다. 두 요청은 한 줄만 다릅니다.

```

```

| 요청 | 3번 "다음 주까지 할 일" | 4번 "확인이 필요한 것" |
| --- | --- | --- |
| 처음 요청 | 15건 | 2건 |
| 한 줄을 더한 요청 | 11건 | 7건 |

처음 요청의 결과에는 기한이 8월 19일, 20일인 일이 "다음 주까지 할 일"에 들어 있었습니다. 회의록에는 그 일이 끝났는지가 적혀 있지 않습니다. 한 줄을 더하자 그 4건과, 처음 결과의 3번 표에 없던 "벤더 원격 진단 요청서 발송"까지 5건이 "완료 여부 확인"으로 옮겨 갔습니다. 4번 항목은 처음 2건에 5건이 더해져 7건이 됐습니다.

3번 표가 15건에서 4건이 줄어 11건이 된 데에는 이유가 있습니다. 처음 요청을 받은 코딩 에이전트는 "벤더 원격 진단 요청서 발송"을 3번 표에서 스스로 뺐습니다. 협력사 미팅 회의록에 요청서가 접수됐다는 문장이 있어 끝난 일로 판단했다고 결과 파일의 3번 표 아래에 적었습니다. 한 줄을 더한 요청에서는 이 일도 "완료 여부 확인"에 들어갔습니다. 요청에 적지 않은 판단을 코딩 에이전트가 했고, 그 사실은 결과 파일을 끝까지 읽어야 알 수 있습니다.

기한이 작성일과 같은 8월 21일인 일 3건은 두 결과 모두 3번 표에 남았습니다. 요청이 "작성일보다 앞선 일"이라고 했기 때문입니다. 당일이 기한인 일을 어떻게 처리할지 정하려면 요청에 한 줄을 더 적어야 합니다.

## 핵심 정리

- 코딩 에이전트는 내 컴퓨터의 작업 폴더에서 파일을 직접 읽고 쓰며, 작업이 끝날 때까지 도구를 골라 실행하고 결과를 확인하는 일을 되풀이합니다.
- 자료가 폴더에 여러 파일로 있고 결과를 파일로 남겨야 하는 일은 코딩 에이전트에 맡깁니다.
- 파일이 바뀌기 전에는 권한 요청에서 파일 경로와 바뀌는 내용을 읽습니다. 묻지 않고 실행하는 모드가 기본값인 코딩 에이전트도 있으므로 첫 요청 전에 권한 모드를 확인합니다.
- 되돌리기로 복원되지 않는 변경이 있습니다. 되돌릴 수 없으면 곤란한 폴더는 사본을 만들어 두고 맡깁니다.
- 요청에는 목적, 입력, 출력, 제약, 끝난 뒤 보고할 것을 적습니다. 적지 않은 부분은 모델이 정하고, 실행할 때마다 다를 수 있습니다.
- 코딩 에이전트가 끝났다고 답한 것은 근거가 아닙니다. 개수를 세고, 원문과 대조하고, 검사 스크립트로 판정합니다. 검사 스크립트와 정답은 작업 폴더 밖에 두고, 작업 폴더 밖의 파일을 묻지 않고 읽는 코딩 에이전트는 묻게 설정합니다.

## 자가점검

**1.** 채팅과 코딩 에이전트의 차이로, 제품이 바뀌어도 성립하는 것은 무엇입니까?

- A. 채팅은 글로만 답하고 코딩 에이전트만 파일을 만든다
- B. 코딩 에이전트는 작업 폴더의 파일을 직접 읽고 쓰며, 끝날 때까지 도구를 골라 실행하는 일을 되풀이한다
- C. 코딩 에이전트는 코드를 작성하는 일에만 쓸 수 있다

:::정답
**B.** 파일을 첨부받고 만들어 주는 채팅 서비스도 있으므로 A는 제품에 따라 다릅니다. 코딩 에이전트는 이 파트처럼 문서 작업에도 쓸 수 있습니다.
:::

**2.** 권한 요청이 나왔을 때 허용하기 전에 읽어야 하는 것을 두 가지 이상 써 보세요.

:::정답
어느 파일인지(경로가 작업 폴더 안인지, 요청한 결과 파일이 맞는지), 무엇이 바뀌는지(새 파일인지, 있던 파일의 어느 줄인지), 명령이라면 어떤 명령인지를 읽습니다. 요청한 일과 관계없는 파일이거나 작업 폴더 밖의 경로이면 거부합니다.
:::

**3.** 코딩 에이전트가 "회의록 10개를 모두 읽고 요약표를 저장했습니다. 미기재는 5칸입니다"라고 답했습니다. 이 응답만으로 결과를 다른 사람에게 보내면 안 되는 이유는 무엇입니까?

:::정답
응답은 모델이 생성한 글이라 결과가 맞다는 근거가 되지 않습니다. 결과 파일을 열어 행 수와 "미기재" 칸 수를 직접 세고, 행 몇 개를 원문과 대조해야 합니다. 형식처럼 규칙으로 확인할 수 있는 것은 검사 스크립트로 판정합니다.
:::

**4.** 검사 스크립트와 풀이를 작업 폴더 밖에 두는 이유는 무엇입니까?

- A. 작업 폴더 안에 두면 코딩 에이전트가 검사 기준을 읽고 결과를 거기에 맞출 수 있어서
- B. 작업 폴더 안의 파이썬 파일은 실행되지 않아서
- C. 작업 폴더의 파일 수가 많으면 요금이 늘어서

:::정답
**A.** 코딩 에이전트는 작업 폴더의 파일을 묻지 않고 읽을 수 있습니다. opencode는 기본 설정에서 작업 폴더 밖의 파일도 묻지 않고 읽으므로, 설정에 `external_directory` 규칙을 적어 묻게 합니다. 검사 기준을 읽고 맞춘 결과는 검사를 통과해도 요청이 좋았기 때문인지 알 수 없습니다.
:::

**5.** "회의록을 표로 정리해서 저장해 주세요"라는 한 줄 요청의 결과를 다음 단계의 프로그램이 받아서 쓰기 어려운 이유를 설명해 보세요.

:::정답
파일 이름, 표의 수, 열, 날짜 표기, 빈칸의 표기를 모두 모델이 정하기 때문입니다. 예제 3-3에서는 파일 이름이 `회의록_정리.md`였고 빈칸을 "정하지 않음"이라고 적었습니다. 다음에 보내면 다르게 정할 수 있습니다. 받는 쪽이 기대하는 것을 요청의 출력과 제약에 적어야 합니다.
:::

**6.** 되돌리기와 새 세션은 각각 언제 사용합니까? 새 세션에서 유지되는 것과 유지되지 않는 것도 함께 써 보세요.

:::정답
되돌리기는 결과가 틀렸거나 요청을 고쳐 다시 받고 싶을 때 사용합니다. 고른 메시지를 보내기 전의 상태로 대화와 파일이 돌아갑니다. 새 세션은 주제가 바뀔 때 사용합니다. 작업 폴더의 파일은 유지되고 앞 세션의 대화는 유지되지 않으므로, 이어 갈 내용은 파일로 남깁니다.
:::

### 추가한 내용

- "이 파트에서 만드는 것" 절: 입력과 출력의 예, 실습 폴더의 구성.
- "요청 쓰는 법" 절: 요청의 다섯 요소와 예제 3-3.
- 코딩 에이전트별 조작 방법 표(터미널의 Claude Code, VS Code 확장, opencode).
- opencode의 기본 설정이 파일 수정, 셸 명령, 작업 폴더 밖의 파일 접근을 묻지 않는다는 점과 설정 예, 설정 파일의 위치.
- Claude Code의 되돌리기 메뉴에서 대화와 파일을 함께 되돌리는 선택지("Restore code and conversation").
- 검사 스크립트 `check.py`와 사람이 만든 요약표 예시, 정답과 검사 파일을 작업 폴더 밖에 두는 이유.
- "미기재" 칸 수가 회의록의 해석에 따라 4칸과 5칸으로 달라진다는 점.
- 코딩 에이전트가 요청에 없는 판단(끝난 일로 보고 표에서 뺌, 담당을 "협력사"로 적음)을 했다는 관찰.

### 고친 내용

- "채팅 AI는 방법을 알려 주고, Claude Code는 결과 파일까지 만듭니다"(p.217) → 작업 폴더에서 일한다는 점과 도구를 골라 실행하며 되풀이한다는 점으로 설명. 파일을 만들어 주는 채팅 서비스도 있어 원본의 대비는 제품에 따라 맞지 않음.
- "확인 루프"(p.215, 218) → "에이전트 루프". 다른 자료에서 찾아볼 때 쓰는 이름에 맞춤.
- "권한 카드", "되감기", "수동"(p.215, 223) → "권한 요청", "되돌리기", "묻는 모드". 용어집 표기에 맞춤. "수동"은 Claude Code 문서의 "Manual"(설정값 `default`)에 해당하므로 조작 표에 화면 표시("manual mode on", "Manual")를 함께 적음.
- "셸 명령으로 바뀐 것은 되돌리지 않습니다"(p.236) → Claude Code는 파일 편집 도구로 고친 적이 없는 파일이 셸 명령으로만 바뀐 경우를 추적하지 않는다고 고침(공식 문서, 2026-11-23 확인).
- "권한은 수동으로 둡니다. 처음에는 자동일 수 있으니"(p.223) → 코딩 에이전트마다 기본값이 다르므로 첫 요청 전에 권한 모드를 확인한다고 씀.
- 실측 숫자 "미기재 5칸", "할 일 16건과 확인 2건이 11건과 7건으로"(p.247-248) → 직접 실행한 결과(5칸, 15건과 2건이 11건과 7건으로)로 바꾸고, 숫자가 해석에 따라 달라지는 이유를 본문에 적음.
