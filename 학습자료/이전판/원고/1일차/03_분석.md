# 1일차 파트 3 "코딩 에이전트 시작하기" 분석

대상: 원본 강의안 p.211–250(파트 03), 실습 폴더 `day01-cc`(회의록 10건, 주간 보고 양식, 요청 글 9개), 답안 양식의 미션 3 칸.
실행 방식에 관한 공통 결정은 `00_분석.md`에 있다. 이 문서는 확인 후 교재에 넣지 않는다.

**사용자 답 (2026-11-19).** (1) 동료들이 주로 쓰는 도구는 터미널의 Claude Code, opencode, VS Code 안의 Claude Code 확장이다. 도구별 표는 이 세 가지를 기준으로 쓰고, 데스크톱 앱의 Code 탭은 다루지 않는다. (2) 하위 에이전트로 얻은 실행 결과를 실어도 된다.

코드를 모르는 사람도 첫날 코딩 에이전트에 문서 작업을 맡겨 본다는 설계가 좋다. 재료도 잘 만들었다. 회의록 10건이 형식이 모두 다르고(안건 목록, 메모, 표, 받아쓰기, 메일) 담당이나 기한이 일부러 빠져 있어, 결과를 원문과 대조해야 하는 이유가 드러난다.
문제는 세 가지다.

1. **절반이 특정 앱의 화면 조작이다.** 로그인, 폴더 선택기, 버튼 위치는 앱이 바뀌면 낡고, 터미널이나 opencode를 쓰는 사람에게는 맞지 않는다.
2. **"맡기는 법"이 없다.** 요청 글이 모두 주어져 있어 복사해 보내기만 한다. 요청에 무엇을 적어야 하는지는 "오전의 4원칙 그대로"라는 한 줄뿐이다.
3. **검증이 눈으로 세는 것뿐이다.** 행 수와 "미기재" 칸 수를 직접 세어 답안에 적는다. 2일차 실습 4는 검사 스크립트로 판정하는데 1일차에는 그 준비가 없다.

설계서 8절 3번의 결정(사내에서 Claude Code와 opencode를 쓴다. 두 도구 어느 쪽으로도 할 수 있게 쓰고 특정 도구의 화면 설명은 줄인다)을 그대로 따른다.

## 2. 학습 목표 (제안)

이 파트를 마치면 다음을 할 수 있다.

1. 채팅과 코딩 에이전트의 차이를 작업 폴더, 도구, 에이전트 루프로 설명하고, 일을 어느 쪽에 맡길지 고른다.
2. 권한 요청에서 무엇이 바뀌는지 읽고 허용하거나 거부한다. 중지, 되돌리기, 새 세션을 상황에 맞게 쓴다.
3. 폴더의 자료로 결과 파일을 만드는 작업을 목적, 입력, 출력, 지킬 것을 갖춘 요청으로 쓴다.
4. 결과 파일을 원문과 대조하고 검사 스크립트로 판정한다. 요청 한 줄을 바꿔 결과가 어떻게 달라지는지 숫자로 비교한다.

## 4. 고칠 내용

1. **"채팅 AI는 방법을 알려 주고, Claude Code는 결과 파일까지 만듭니다" (p.217).** 채팅 앱도 파일을 첨부받고 만들어 주는 기능이 있어 이 대비는 제품에 따라 맞지 않는다. 변하지 않는 차이는 두 가지다. 코딩 에이전트는 내 컴퓨터의 작업 폴더에서 일하고, 끝날 때까지 도구를 골라 쓰며 반복한다. 이 두 가지로 설명한다.
2. **권한 모드와 조작의 이름 (p.223, 234–239).** "수동", "권한 카드", "되감기"는 데스크톱 앱의 화면 이름이다. 터미널의 Claude Code와 opencode는 이름과 방법이 다르다. 본문은 개념으로 쓰고(권한 요청, 중지, 되돌리기, 새 세션), 도구별 이름과 방법은 표 하나로 모은다. 표의 내용은 본문을 쓸 때 각 도구의 공식 문서로 확인하고 확인한 날짜를 적는다.
3. **"되감기는 셸 명령으로 바뀐 것은 되돌리지 않습니다" (p.236).** 중요한 주의점이다. 공식 문서로 확인해 유지하고, opencode의 되돌리기가 어떻게 동작하는지도 확인해 적는다. 확인하지 못하면 "도구의 문서를 확인한다"로 쓴다.
4. **예제 3-1의 채팅 응답 (p.228).** "저장은 직접 하셔야 합니다"는 그 채팅 화면의 응답이다. 노트북의 `Chat`으로 같은 요청을 보내 실제 응답을 싣는다.
5. **실측 숫자 (p.247–248).** "미기재 5칸", "할 일 16건과 확인 2건이 11건과 7건으로"는 요청 글의 해석에 따라 달라질 수 있다. 원문 10건에서 정답표를 만들고, 그 표로 결과를 판정한다.

## 7. 실행 결과를 얻는 방법과 확인하지 못하는 것

이 파트의 실행 결과는 코딩 에이전트를 실제로 돌려야 얻는다. 지금 작업 환경의 터미널에는 `claude`와 `opencode` 명령이 없다(2026-11-19 확인).

- **요약표와 주간 보고의 결과**: 실습 폴더의 사본에서 Claude Code의 하위 에이전트에 요청 글을 그대로 보내 얻을 수 있다. 실제 Claude Code가 실행한 결과이지만, 데스크톱 앱이나 터미널에서 사람이 새 세션에 보낸 것과 경로가 같지는 않다. 교재에는 어떻게 얻은 결과인지 적는다.
- **권한 요청, 중지, 되돌리기의 화면과 동작**: 내가 조작해 보일 수 없다. 공식 문서로 확인한 내용만 쓰고, 화면은 싣지 않는다.
- **opencode에서의 실행**: 확인할 수 없다. 도구별 표의 opencode 칸은 공식 문서에서 확인한 것만 적고, 확인하지 못한 칸은 비운다.

사용자가 실습 4를 한 번 실행해 결과 폴더를 주시면 그 결과를 싣는 것이 가장 정확하다.

## 8. 확인해 주실 것

1. **도구.** 동료들이 주로 쓰는 것이 Claude Code 데스크톱 앱인지, 터미널의 Claude Code인지, opencode인지. 도구별 표의 기준과 예시 화면을 그쪽에 맞춘다.
2. **실행 결과(7절).** 하위 에이전트로 얻은 결과를 실어도 되는지, 아니면 직접 실행한 결과를 주실지.
3. **실습에서 요청 글을 직접 쓰게 하는 것(6.3).** 원본은 복사해 보내는 방식이다.
4. **"요청 쓰는 법" 절을 추가하는 것(6.1의 4절).** 원본에 없는 내용이다.
