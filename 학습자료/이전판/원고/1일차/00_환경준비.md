# 실습 환경 준비

1일차의 예제에서는 프롬프트(모델에 입력하는 글)를 모델에 보내고 응답을 읽습니다. 이 장에서는 예제를 실행하는 방법과 필요한 준비를 안내합니다.

## 예제를 실행하는 두 가지 방법 {추가}

- **사내 LLM API(OpenAI 호환 API)나 Anthropic API를 쓸 수 있으면 학습 노트북으로 실행합니다.** 노트북의 셀을 실행하면 프롬프트가 API로 전송되고 응답이 셀 아래에 출력됩니다. 교재의 실행 결과도 이 방법으로 얻었습니다.
- **API를 쓸 수 없으면 회사가 허용한 채팅 서비스를 씁니다.** 교재의 프롬프트를 복사해 채팅 화면에 붙여 넣고 응답을 읽습니다.

채팅 서비스로 실행할 때는 노트북이 하던 일을 직접 합니다.

- 예제의 프롬프트는 파이썬 문자열로 적혀 있습니다. 따옴표와 `\n`은 빼고 글만 옮깁니다.
- `read_material()`로 재료를 넣는 예제는 `노트북/data/1일차`에서 그 파일의 내용을 열어 함께 붙여 넣습니다.
- 같은 프롬프트를 여러 번 보내 결과를 세는 예제는 새 채팅을 열어 직접 반복합니다.
- 실습 노트북의 테스트 셀은 API를 호출하므로 채팅 서비스로는 실행할 수 없습니다. 풀이 노트북의 해설과 결과를 읽고 자신의 답과 비교합니다.

어느 방법으로 해도 응답은 교재의 실행 결과와 다를 수 있습니다. 모델이 다르면 응답이 다르고, 같은 모델도 실행할 때마다 응답이 달라질 수 있습니다(파트 1의 "LLM이 글을 생성하는 방식" 절). 교재와 비교할 것은 문장이 같은지가 아니라 같은 현상이 나타나는지입니다.

:::주의
회사가 허용하지 않은 외부 서비스에는 예제의 프롬프트도 입력하지 않습니다. 교재의 재료는 모두 지어낸 가상 데이터이지만, 어떤 서비스를 쓸 수 있는지는 회사의 기준을 따릅니다.
:::

## 준비물 {추가}

| 준비물 | 설명 |
| --- | --- |
| Python 3.10 이상과 Jupyter | 사내 PC의 Jupyter나 VS Code의 노트북에서 실행합니다 |
| `노트북` 폴더 | 학습 노트북과 실습 노트북, 공통 호출 함수 `llm.py`, 실습 테스트 `checks_d1.py`, `checks_d1_2.py`, 재료 폴더 `data`, 파트 3에서 쓰는 `코딩도구_실습_1일차` 폴더가 들어 있습니다 |
| API 접근 정보 | Anthropic API 키, 또는 사내 LLM API의 주소, 키, 모델 이름 |

필요한 패키지는 다음 명령으로 설치합니다.

```bash
python -m pip install anthropic openai pandas pydantic openpyxl jupyter
```

API 키와 환경 변수를 설정하는 방법은 학습 노트북의 "준비" 절에 있습니다. [2일차 교재의 "실습 환경 준비"](2일차.html#실습-환경-준비)에도 같은 내용이 있습니다. `setx`로 환경 변수를 설정해 두면 모든 일자의 노트북에서 그대로 씁니다. "준비 (1)" 셀에서 입력한 값은 커널이 살아 있는 동안만 쓰이므로, 노트북을 새로 열거나 커널을 다시 시작하면 다시 입력합니다.

노트북을 `노트북` 폴더에서 열고 "준비 (1)", "준비 (2)" 셀을 차례로 실행합니다. 두 셀이 오류 없이 끝나고 마지막 줄에 모델의 응답(보통 `준비 완료`)이 나오면 연결된 것입니다. 응답 문구는 모델에 따라 조금 다를 수 있습니다.

## 예제 코드 읽는 법 {추가}

1일차의 예제 코드는 대부분 프롬프트를 보내고 응답을 확인하는 데 씁니다. 예제에 자주 나오는 코드는 다음과 같습니다.

| 코드 | 뜻 |
| --- | --- |
| `chat = llm.Chat()` | 새 채팅을 엽니다. 앞에서 한 대화는 이 채팅에 들어 있지 않습니다 |
| `chat.say('프롬프트')` | 프롬프트를 보내고 응답을 출력합니다. `show=False`를 함께 주면 출력하지 않고 보내기만 합니다. 같은 `chat`에서 `say()`를 다시 호출하면 같은 대화가 이어집니다 |
| `llm.Chat(model='소형')` | 프롬프트를 보낼 모델의 등급을 고릅니다. 모델 등급은 같은 제공사의 모델을 능력과 가격으로 나눈 구분입니다. 소형, 기본, 대형이 있고, 적지 않으면 기본 등급으로 보냅니다 |
| `llm.Chat(max_tokens=8000)` | 응답 하나에서 모델이 생성할 수 있는 토큰 수의 상한(최대 출력 토큰)을 정합니다. 적지 않으면 4,000토큰입니다. 상한에 닿으면 응답이 중간에 끊깁니다. 토큰은 파트 1의 "토큰과 컨텍스트 윈도우" 절에서 설명합니다 |
| `llm.Chat(system='...')` | 시스템 프롬프트를 넣어 채팅을 엽니다. 시스템 프롬프트는 파트 2의 "시스템 프롬프트와 멀티턴" 절에서 설명합니다 |
| `chat.last` | 마지막 응답입니다. `chat.last.text`는 응답 텍스트, `chat.last.output_tokens`는 출력 토큰 수, `chat.last.seconds`는 걸린 시간(초), `chat.last.stop_reason`은 종료 이유입니다 |
| `chat.history` | 이 채팅에서 지금까지 주고받은 메시지의 목록입니다. 메시지마다 `role`과 `content`가 든 dict입니다 |
| `read_material('파일 이름')` | 재료 폴더(`data/1일차`)의 파일을 읽어 문자열로 돌려줍니다 |
| `llm.send(메시지 목록)` | 채팅을 열지 않고 요청 한 번을 보내 응답을 돌려줍니다. 응답의 `input_tokens`는 입력 토큰 수입니다 |
| `llm.count_tokens(메시지 목록)` | 보내기 전에 입력 토큰 수를 셉니다. 세는 기능이 없는 API이면 `None`을 돌려줍니다 |

종료 이유는 모델이 생성을 멈춘 이유입니다. `llm.py`는 API가 돌려준 값을 다음 네 가지로 바꿔 `chat.last.stop_reason`에 넣습니다.

- `end`: 정상 종료입니다. Anthropic API의 `end_turn`, `stop_sequence`, OpenAI 호환 API의 `stop`입니다.
- `max_tokens`: 응답이 잘렸습니다. 최대 출력 토큰에 닿은 경우(Anthropic API의 `max_tokens`, OpenAI 호환 API의 `length`)와 컨텍스트 윈도우가 가득 찬 경우(Anthropic API의 `model_context_window_exceeded`)입니다.
- `refusal`: Anthropic API에서는 모델이 응답을 거절한 경우(`refusal`)입니다. OpenAI 호환 API에서는 서버의 콘텐츠 필터가 출력을 막은 경우(`content_filter`)와 응답의 `refusal` 필드에 거절 사유가 온 경우입니다.
- `other`: 그 밖의 값입니다.

종료 이유가 `end`가 아니면 `say()`는 응답 아래에 `[종료 이유: ...]`로 시작하는 줄을 하나 더 출력합니다.

`llm`과 `read_material()`은 "준비" 셀이 만들어 둡니다. 같은 셀이 `os`, `json`, `time`, `pd`(pandas), `ThreadPoolExecutor`를 불러 두고, 재료 폴더의 경로를 `DATA`에 넣어 둡니다. 예제 코드에 이 이름이 정의 없이 나오면 준비 셀에서 정의한 것입니다. `Chat`이 안에서 하는 일은 2일차 파트 1에서 직접 만들어 봅니다.
