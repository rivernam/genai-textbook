원본의 뼈대는 좋다. "한 건을 처리하는 코드를 백 건에 쓰려면 무엇을 더해야 하는가"라는 흐름이 분명하다.
문제는 세 가지다.

1. **개념 설명이 얇다.** 슬라이드 한 줄 정의와 코드로 넘어가서, 토큰·컨텍스트 윈도우·thinking·rate limit 같은 개념이 "무엇이고 왜 그런지" 없이 등장한다. 상당 부분을 1일차 기억에 기댄다.
2. **실습이 "그대로 실행"이다.** 미션 1은 준비된 셀을 실행하고 값 두 개를 바꾸는 것이라, 스스로 코드를 쓰거나 판단할 일이 거의 없다.
3. **Claude 한 곳에 묶여 있다.** 사내 API(OpenAI 호환)를 쓰는 동료는 같은 개념이 자기 환경에서 어떻게 보이는지 알 수 없다.

## 2. 학습 목표 (제안)

이 파트를 마치면 다음을 할 수 있다.

1. LLM API 호출의 요청과 응답이 어떤 값으로 이루어지는지 설명하고, 코드로 직접 호출해 응답에서 답·토큰 수·종료 이유를 읽는다.
2. API 서버가 대화를 기억하지 않는다는 점을 설명하고, 대화 이력을 코드로 관리하며 이력이 비용에 주는 영향을 숫자로 말한다.
3. 토큰과 단가로 요금을 계산하고, 대량 작업을 보내기 전에 비용을 추정한다.
4. 정답을 아는 표본으로 정확도, 시간, 요금을 측정하고, 그 결과를 근거로 모델 등급을 고른다.
5. 실패를 "다시 보낼 것", "바로 멈출 것", "예외 없이 끝났지만 쓸 수 없는 것"으로 나누고 각각을 코드로 처리한다.
6. 한 건을 처리하는 코드를 입력 검사·재시도·응답 검사·실패 목록을 갖춘 일괄 처리 코드로 확장한다.

## 4. 고칠 내용

1. **`temperature` 설명 (p.63).** 원본은 "최신 SDK에 없음 · 넣으면 TypeError"라고 한다. 실행해 보니 이 설명은 사실이다(anthropic SDK 2.1.0에서 `temperature`를 넣으면 `TypeError`가 난다. 2026-11-18 확인). 처음 분석에서 이 문장을 "틀림"으로 분류한 것은 내 판단 착오였다. 다만 원본에는 이유가 없다. 최신 Claude 모델이 샘플링 파라미터(`temperature`, `top_p`, `top_k`)를 받지 않게 되면서 SDK에서도 인자가 빠진 것이고, OpenAI 호환 API는 대개 `temperature`를 받는다. 교재에는 샘플링 파라미터가 무엇인지, 최신 Claude 모델에서는 지정할 수 없다는 점, 사내 모델은 문서를 확인해야 한다는 점을 함께 쓴다.
2. **수치 불일치 (p.39–40).** 실행 결과는 출력 112토큰인데 다음 장은 "출력 115에는 생각 토큰 62도"라고 한다. 예제를 새로 실행하므로 한 번의 실행 결과로 통일한다.
3. **재시도 횟수 계산 (p.108–110).** "한 번 실패 확률 6%면 세 번에 0.022%"는 실패가 서로 독립일 때만 맞다. 서버 과부하나 요청 한도 초과는 연달아 일어나므로 실제로는 더 많이 남는다. 계산은 유지하되 이 전제를 밝힌다.
4. **깨진 실행 결과 (p.57, p.133 등).** 슬라이드 변환 과정에서 줄이 뒤섞였다. 새로 실행한 결과로 대체한다.
5. **경량 모델.** 원본은 `claude-haiku-4-5`를 쓴다. 현재는 Haiku 5.5가 있고 단가가 다르다. 교재의 Claude 실행 예시는 현행 모델로 실행하고, 모델 이름과 단가에는 확인 날짜를 적는다. (작성자 판단. 원본 모델을 유지하길 원하면 알려 달라.)

### 6.3 실습

| 번호 | 과제 | 완료 기준 | 목표 |

실습 3과 실습 4는 같은 10가지 기준을 쓴다. 실습 3에서 직접 써 본 뒤 실습 4에서 도구에 맡기면, 도구가 낸 결과가 맞는지 스스로 판정할 수 있다. 실습 4는 가짜 응답기로 검사하므로 API 요금이 들지 않는다.

원본 미션 1과의 차이: 원본은 준비된 코드를 실행하고 값을 바꾼다. 새 실습은 핵심 함수를 직접 쓰고, 확인 셀이 맞았는지 알려 준다. 각 실습에 단계별 힌트와 풀이를 접어 둔다.

### 6.4 재료

| 원본 재료 | 처리 | 이유 |
