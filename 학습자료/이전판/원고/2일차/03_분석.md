# 2일차 파트 3 "RAG의 원리와 임베딩 검색" 분석

대상: 원본 강의안 2일차 p.293–424(파트 03, 마무리, 부록), 예제 노트북의 예제 3-1~3-3, 실습 노트북의 미션 3, 재료(`corpus` 문서 253건, `corpus_manifest.csv`, `2일차_미션3_재료.txt`), 퀴즈의 파트 3 문항.
본문을 쓰기 전에 방향을 확인받기 위한 문서이고, 교재에는 넣지 않는다.

이 파트는 지금까지 만들지 않았다. 2일차 교재에는 파트 1, 2만 있다. 3일차가 이 파트에서 만든 인덱스를 첫 예제에서 다시 만들어 쓰므로, 3일차보다 먼저 만든다.

**사용자 답 (2026-11-24).** 임베딩 모델: 사내에서 Hugging Face 프록시 주소를 제공한다. 주소는 교재에 적지 않고, 설정할 수 있게 안내한다. → `embed.py`가 환경 변수 `HF_ENDPOINT`를 쓰고, 설정하지 않았으면 모델을 처음 불러올 때 주소를 물어본다(화면과 노트북 파일에 남지 않음). 환경 준비에 "임베딩 모델 준비" 절을 넣었다. 8절의 2, 3, 4번은 명시적 답 없이 제안대로 진행했다.

## 3. 학습 목표 (제안)

이 파트를 마치면 다음을 할 수 있다.

1. 모델이 사내 문서를 모른다는 점을 확인하고, 문서를 모두 붙이는 방식과 찾아서 붙이는 방식의 입력 토큰과 요금을 비교해 검색이 필요한 이유를 숫자로 설명한다.
2. 키워드 검색이 문서에 점수를 매기는 방법을 설명하고, 한국어에서 낱말을 나누는 단위가 결과를 어떻게 바꾸는지 실행해 보인다.
3. 임베딩과 코사인 유사도를 설명하고, 문서를 벡터 인덱스로 만들어 질문과 가까운 문서를 찾는 `search()`를 작성한다.
4. 정답 문서를 아는 질문 세트로 recall@k를 측정해 두 검색 방법을 비교한다.
5. 검색 1위 문서를 열어 질문에 답하는 문서인지 판정하고, 점수만으로 판정하면 안 되는 이유를 설명한다.
6. 찾은 문서를 프롬프트에 붙여 답하게 하고, RAG가 검색과 생성의 두 단계로 이루어진다는 점을 설명한다.

## 4. 고칠 내용

1. **"키워드 검색은 253건 전부 0점"이라는 결론 (p.330–335, 357).** 원본의 0점은 키워드 검색의 한계가 아니라 낱말을 공백으로 나눈 탓이다. "칠러가"와 "칠러"를 다른 낱말로 세었기 때문이다. 원본도 p.335에서 "조사가 붙은 한국어"가 직접 원인이라고 적었지만, 결론은 "그래서 뜻으로 찾는 임베딩 검색을 씁니다"로 넘어간다. 글자 2~3개 단위로 나누는 TF-IDF(`analyzer='char_wb'`, 한 줄만 바꾼다)로 실행하면 다섯 질문의 정답 순위가 임베딩 검색과 같다. 이대로 실으면 독자는 "키워드 검색은 한국어에서 쓸 수 없다"고 잘못 배우고, 4일차의 하이브리드 검색(키워드와 임베딩을 합침)과도 맞지 않는다.
   고치는 방향: 낱말 단위로 0점이 나오는 것을 먼저 보이고, 나누는 단위를 바꾸면 찾는다는 것을 이어서 보인다. 그다음 키워드 검색이 정말 놓치는 경우(현장 말과 문서 말이 다른 경우, 약어와 풀어 쓴 말)를 그 경우에 해당하는 질문으로 따로 보인다. 다섯 질문으로는 두 방법의 차이를 말할 수 없으므로 5절 4번처럼 질문 세트를 늘린다.
2. **"문서를 붙이면 환각이 줄어듭니다", 1일차 실습의 지어내기 표 (p.299, 303).** 표의 내용(경량 모델이 조항을 통째로 지어냄)은 1일차 교재를 만들 때 현행 Claude 모델에서 재현되지 않았다. 1일차 교재에도 싣지 않았다. 이 표는 삭제하고, 예제 3-1의 실제 응답(근거 없이 물으면 "확인할 수 없다"고 답함)으로 설명한다.
3. **입력 토큰과 요금의 숫자 (p.313–318, 380–382).** 660토큰, 67,917토큰, 103배, $0.136은 당시 모델의 실행 결과다. 다시 실행한 값으로 바꾼다. 단가는 2일차 파트 1의 표와 같은 값을 쓴다.
4. **"전부 붙이면 2.0초"와 그 결론 (p.316–318).** 원본은 정답을 맞혔고 2초면 끝났다고 보여 준 뒤 토큰 요금만 문제 삼는다. 전부 붙이는 방식의 한계는 요금만이 아니다. 문서가 컨텍스트 윈도우를 넘으면 보낼 수 없고, 문서가 바뀔 때마다 전체를 다시 보낸다. 이 두 가지를 더한다. 문서 수가 적고 질문이 드물면 전부 붙이는 쪽이 간단하다는 점도 적는다. 실행 시간은 한 번 측정한 값이라 싣지 않는다.
5. **"임베딩 점수와 검색 순위는 같은 값이 나옵니다" (p.424).** 같은 모델, 같은 라이브러리에서는 내 실행에서도 소수 셋째 자리까지 같았다. 다만 라이브러리 버전과 하드웨어에 따라 끝자리는 달라질 수 있으므로 "거의 같은 값"으로 쓴다.
6. **"문서 253건 임베딩 0.3초" (p.353).** GPU에서 측정한 값이다. 사내 PC의 CPU에서는 수십 초가 걸린다. 직접 실행한 값(CPU)으로 쓰고, 인덱스를 파일로 저장해 다시 쓰는 방법을 한 문단 넣는다(3일차에서 자세히 다룬다).
7. **recall@k를 질문 다섯 개로 측정 (p.361–366).** 다섯 개에서 80%와 100%는 한 문제 차이다. 2일차 파트 1에서 "20건은 작은 표본"이라고 쓴 것과 같은 문제다. 질문 세트를 늘리고(5절 4번), 표본이 작으면 한두 건으로 숫자가 크게 움직인다는 점을 적는다.
8. **용어.** "숫자 384개", "머리말"(접두어), "검색 적중률" → 벡터의 차원(384차원), 접두어(prefix), recall@k. "뜻으로 찾는다" → 의미가 비슷한 문서를 찾는다(시맨틱 검색, semantic search)로 쓰고 처음에 정의한다. "낱말 목록" → 어휘(vocabulary).

## 5. 추가할 내용

1. **이 파트에서 만드는 것.** 입력(문서 253건과 질문)과 출력(질문마다 문서 순위, 그리고 찾은 문서를 붙여 받은 응답)의 예를 첫 절에 보인다.
2. **임베딩 모델이 무엇인가.** 원본은 "문장을 숫자 384개로 바꾼 것"이라고만 한다. LLM과 다른 모델이라는 점, 글을 생성하지 않고 벡터만 낸다는 점, 문서와 질문을 같은 모델로 바꿔야 비교할 수 있다는 점, 모델마다 차원과 지원 언어가 다르다는 점을 더한다.
3. **정답이 없는 질문.** 원본은 p.383에서 한 줄로만 말한다("정답이 없는 질문도 1위 문서는 반드시 나옵니다"). 코퍼스에 답이 없는 질문을 실제로 검색해 1위 점수가 다른 질문과 비슷하게 나오는 것을 보인다. 점수 하한으로 가려낼 수 없다는 점이 5번 목표의 근거다.
4. **정답 문서를 아는 질문 세트.** 다섯 개를 20개 안팎으로 늘린다. 현장 말투, 문서 말투, 약어, 구판과 신판이 함께 있는 문서, 코퍼스에 답이 없는 질문을 섞는다. `corpus_manifest.csv`의 제목과 본문을 읽고 새로 작성하며, 질문마다 정답 문서 번호를 붙이고 실행해 확인한다.
5. **구판과 신판.** 원본에서 "He 배면압" 질문은 v1.2가 v2.0보다 앞에 온다(0.913과 0.912). 좋은 사례인데 원본은 "앞에 온 문서"로만 표시한다. 임베딩은 어느 쪽이 최신인지 모른다는 점을 본문에서 설명하고, 해결(메타데이터로 필터링)은 3일차로 넘긴다.

### 7.3 실습

2일차의 실습 번호는 파트 1이 1~4, 파트 2가 5~7이다. 이 파트는 실습 8, 9로 한다.

| 번호 | 과제 | 완료 기준 | 목표 |

## 8. 확인해 주실 것

1. **임베딩 모델을 사내에서 쓰는 방법.** 설계서 8절 2번에 남아 있는 질문이다. 예제는 `intfloat/multilingual-e5-small`(약 470MB)을 Hugging Face에서 내려받아 PC에서 실행한다. 사내망에서 내려받을 수 있는지, 아니면 사내 임베딩 API(OpenAI 호환 `/v1/embeddings`)가 있는지에 따라 `embed.py`의 경로가 달라진다. 답이 없으면 로컬 모델을 기본으로 하고, 모델 폴더를 따로 받아 경로를 지정하는 방법을 환경 준비에 적는다.
2. **키워드 검색의 결론을 고치는 것(4절 1번).** 원본의 "키워드는 0점, 임베딩은 1위"라는 대비가 사라지고, "낱말을 나누는 단위를 고치면 키워드 검색도 찾는다. 두 방법이 놓치는 경우가 다르다"로 바뀐다. 강의에서 들은 내용과 달라지는 부분이다.
3. **질문 세트를 20개 안팎으로 늘리는 것(5절 4번)과 실습 8을 새로 만드는 것(7.3절).**
4. **API 사용.** 예제 3-1과 3-7에 API 호출이 7회쯤 필요하다. 전부 붙이기 한 번이 입력 약 6만 8천 토큰이다(소형 모델로 약 0.01달러). 나머지 예제와 실습은 로컬에서 실행한다.
