# 2장 모델은 어떻게 만들어지는가

강의 1일차 파트 1, 6일차 파트 1에 해당합니다.

이 장은 1장의 모델이 어떻게 만들어지는지를 설명합니다. 학습 방식을 알면 모델이 왜 기준일 뒤의 일을 모르는지, 왜 틀린 내용을 그럴듯하게 쓰는지, 왜 짧은 답에도 요금이 많이 드는지를 설명할 수 있습니다.

## 학습 목표

1. 사전 학습이 대량의 글에서 다음 토큰 예측을 학습한다는 것을 손실로 설명하고, 사전 학습만 한 모델(베이스 모델)이 질문에 답하지 않고 글을 이어 쓰는 이유를 설명할 수 있습니다.
2. SFT(supervised fine-tuning), RLHF(reinforcement learning from human feedback), DPO(direct preference optimization)가 각각 어떤 데이터로 모델의 무엇을 바꾸는지 설명할 수 있습니다.
3. 모델에 지식 기준일이 생기는 이유와, 학습 목표가 사실이 아니라 그럴듯한 다음 토큰이어서 환각이 생기는 이유를 설명할 수 있습니다.
4. thinking 모델이 답하기 전에 토큰을 더 생성하는 이유와, 그 토큰이 시간과 요금에 어떻게 나타나는지 설명할 수 있습니다.

예제 2-1~2-3은 PC에서 실행합니다. 예제 2-1은 아주 작은 모델을 직접 학습시키고, 2-2와 2-3은 학습 단계만 다른 공개 모델 두 개를 씁니다. 사전 학습만 마친 Qwen2.5-0.5B와, 같은 모델에 학습을 더한 Qwen2.5-0.5B-Instruct(1장의 모델, "질문에 답하는 법: SFT" 절에서 설명)입니다. 예제 2-4만 API(application programming interface)로 모델을 호출합니다. 생성한 문장, 손실의 소수점 아래 숫자, 토큰 수는 PC, 라이브러리 버전, 실행할 때마다 교재와 다를 수 있습니다.

## 사전 학습: 글을 이어 쓰는 법

:::요점
사전 학습은 수조 토큰의 글에서 위치마다 실제 다음 토큰의 확률을 높이도록 모델을 고칩니다. 이렇게 만든 베이스 모델은 질문을 받아도 답하지 않고, 그 질문이 실린 글이 이어질 법한 방향으로 씁니다.
:::

[[사전 학습]](pre-training)은 대량의 글에서 [[다음 토큰 예측]]을 학습하는 첫 단계입니다. 정답은 글에 실제로 이어진 토큰이므로 사람이 정답을 만들 필요가 없고, 그래서 데이터를 아주 많이 쓸 수 있습니다. 예제의 모델은 18조 토큰으로 사전 학습했습니다(Qwen Team, 2024).

얼마나 잘 맞혔는지는 [[손실]](loss)로 나타냅니다. 위치마다 실제 다음 토큰에 준 확률 p로 -log p(자연로그)를 구해 평균한 값이고, 학계에서는 cross-entropy loss라고 부릅니다. 로그를 쓰면 크게 틀린 위치의 손실이 급격히 커지고(아래 그림), 문장 전체의 확률(위치별 확률의 곱)을 위치별 값의 합으로 다룰 수 있습니다.

데이터를 정제하고 토크나이저를 만든 뒤, 모델의 층 수와 벡터 크기를 정하고 모든 파라미터를 무작위 값으로 채웁니다. 이 상태의 모델은 아무 글자나 냅니다. 그다음 글 묶음을 넣고 손실을 계산해 파라미터를 고치는 일을 되풀이합니다. 고치는 방법을 [[경사 하강법]](gradient descent)이라고 하며, 파라미터 하나하나를 손실이 줄어드는 방향으로 조금씩 옮깁니다(자세한 내용은 11장). 이 되풀이에 드는 자원은 매우 큽니다. Llama 3 405B는 15.6조 토큰을 최대 1만 6천여 개의 H100 GPU(graphics processing unit)로 학습했습니다(Meta, 2024).

:::예제 2-1 무작위 모델을 학습시키기
글자 하나를 토큰 하나로 쓰는 아주 작은 모델(파라미터 약 11만 개)을 무작위 값에서 시작해 후공정 문장 30개로 1,000번 고칩니다. 학습 전, 100번, 1,000번 고친 뒤에 같은 시작 글("와이어 본딩은 ")로 생성한 글과 손실을 비교합니다. `generate()`는 준비 셀에 있는 함수로, 1장의 네 단계대로 다음 글자를 샘플링해 붙입니다. PC에서 몇 초 안에 끝납니다.

```python
text = open(f'{DATA}/후공정_문장.txt', encoding='utf-8').read()   # 후공정 문장 30개
characters = sorted(set(text))                                           # 이 예제의 어휘: 글자 하나가 토큰 하나
ids = torch.tensor([characters.index(ch) for ch in text])
inputs = torch.stack([ids[i:i + 8] for i in range(len(ids) - 8)])        # 앞 8글자를 보고
targets = ids[8:]                                                        # 다음 글자를 맞힙니다
torch.manual_seed(0)
tiny_model = torch.nn.Sequential(torch.nn.Embedding(len(characters), 32), torch.nn.Flatten(),
                                 torch.nn.Linear(8 * 32, 256), torch.nn.Tanh(),
                                 torch.nn.Linear(256, len(characters)))   # 파라미터는 무작위 값에서 시작
optimizer = torch.optim.AdamW(tiny_model.parameters(), lr=0.003)        # 손실이 줄어드는 쪽으로 파라미터를 고치는 도구
for step in range(1001):
    batch = torch.randint(len(targets), (64,))                           # 64개씩 묶어
    loss = torch.nn.functional.cross_entropy(tiny_model(inputs[batch]), targets[batch])  # 손실을 계산하고
    optimizer.zero_grad(); loss.backward(); optimizer.step()             # 파라미터를 고칩니다
    if step in (0, 100, 1000):
        print(f'{step:>5}번째 손실 {loss.item():.2f}  생성: {generate(tiny_model, characters, "와이어 본딩은 ")}')
```
:::

학습 전의 모델은 무작위 글자를 내고, 100번 고친 뒤에는 "합니다", "다이" 같은 조각이 나오고, 1,000번 고친 뒤에는 학습한 문장과 비슷한 문장이 나옵니다. 그사이 손실은 5.17에서 0.1 아래로 줄었습니다. 문장이 30개뿐이라 이 모델은 문장을 거의 외웠고, 학습한 글에 없는 "와이어 본딩은" 다음에는 다른 문장의 조각을 이어 붙였습니다. 실제 사전 학습은 같은 일을 수조 토큰으로 하므로, 외우는 대신 글이 이어지는 일반적인 패턴을 익힙니다.

### 베이스 모델

사전 학습만 마친 [[베이스 모델]](base model)이 배운 것은 "이 글 다음에 무엇이 올 법한가"뿐입니다. 그래서 질문을 넣으면 답하지 않고 그 질문이 실린 글이 이어질 법한 내용을 씁니다. 학습한 글에 FAQ 목록처럼 질문 다음에 질문이 오는 글이 있으면, 그 이어짐에도 확률이 붙습니다.

:::예제 2-2 베이스 모델과 instruct 모델
같은 질문을 두 모델에 "질문만"과 "채팅 형식"으로 넣고, 어느 조합에서 답하는 글이 나오는지 봅니다. 채팅 형식은 질문을 사용자의 말로 표시하고 모델의 답 차례를 여는 표시를 붙인 글이며, 이 규칙을 채팅 템플릿(chat template)이라고 합니다(3장). 두 모델 모두 언제나 1위 토큰을 고르므로(greedy decoding) 다시 실행해도 같은 글이 나옵니다.

```python
question = '반도체 후공정에서 다이싱이란 무엇입니까?'
chat_format = tokenizer.apply_chat_template(                  # 채팅 형식의 글을 만듭니다(3장)
    [{'role': 'user', 'content': question}], tokenize=False,
    add_generation_prompt=True)                               # 모델의 답 차례를 여는 표시를 붙입니다
for model_name, model in [('베이스 모델', base_model), ('instruct 모델', instruct_model)]:
    for input_name, text in [('질문만', question), ('채팅 형식', chat_format)]:
        input_ids = tokenizer(text, return_tensors='pt').input_ids
        output = model.generate(input_ids, max_new_tokens=50, pad_token_id=tokenizer.eos_token_id)
        continuation = tokenizer.decode(output[0, input_ids.shape[1]:],   # 입력 뒤에 새로 생성한 토큰만
                                        skip_special_tokens=True)
        print(f'[{model_name}, {input_name}]', continuation.replace('\n', ' / '), '\n')
```
:::

실행 결과를 정리하면 다음과 같습니다.

| | 질문만 | 채팅 형식 |
| --- | --- | --- |
| 베이스 모델 | 질문 뒤에 사이트 이름 같은 말을 붙이고 같은 질문을 되풀이합니다 | 답하는 듯한 문장을 쓰지만 같은 말을 되풀이합니다 |
| instruct 모델 | 웹 문서의 메뉴 같은 글을 이어 씁니다 | 질문에 답하는 문장을 씁니다 |

instruct 모델도 질문만 넣으면 답하지 않습니다. 다음 절의 SFT가 학습시킨 것은 "채팅 형식에서 답 차례가 열리면 답을 쓴다"는 행동이기 때문입니다. 베이스 모델이 채팅 형식에서 답하는 흉내를 낸 것은 어휘에 채팅 형식의 표시 토큰이 이미 들어 있기 때문으로 보입니다. 답의 품질은 두 모델 모두 낮습니다(파라미터 5억 개).

## 질문에 답하는 법: SFT

:::요점
SFT는 질문과 모범 답의 쌍으로 다음 토큰 예측을 이어서 학습합니다. 학습 방식은 사전 학습과 같고, 데이터가 "질문 다음에는 답이 온다"는 글로 바뀐 것입니다.
:::

[[SFT]](supervised fine-tuning, instruction tuning이라고도 함)는 사람이 쓰거나 검수한 모범 답을 채팅 형식으로 감싸, 답 부분을 다음 토큰 예측으로 학습합니다(아래 그림). 질문 다음에 언제나 답이 오는 데이터이므로 "질문을 받으면 답한다"를 익히고, 끝 토큰까지 맞히므로 답을 다 쓰면 멈추는 법도 익힙니다.

## 사람이 고른 답 쪽으로: RLHF와 DPO

:::요점
한 질문에 대한 두 답 가운데 사람이 나은 쪽을 고른 데이터로 모델을 다듬습니다. RLHF는 이 데이터로 점수를 매기는 모델을 만들어 강화 학습하고, DPO는 쌍으로 바로 학습합니다.
:::

이 단계의 데이터는 "질문, 답 A, 답 B, 사람이 고른 쪽"입니다. 모범 답을 쓰는 것보다 고르는 일이 쉬워 데이터를 더 많이 모을 수 있습니다. 말투, 길이, 위험한 요청의 거절, 모르면 모른다고 하기 같은 행동을 여기서 다듬습니다. 모델을 고치는 방법은 두 가지가 널리 쓰입니다(아래 그림).

- [[RLHF]](reinforcement learning from human feedback)는 먼저 사람의 선택을 흉내 내는 [[보상 모델]](reward model)을 학습시킵니다. 보상 모델은 답에 사람이 얼마나 좋아할지 점수(보상, reward)를 매깁니다. 그다음 모델이 생성한 답에 보상 모델이 점수를 매기고, 보상이 높은 답이 더 자주 나오도록 모델을 고칩니다. 이런 학습을 [[강화 학습]](reinforcement learning)이라고 합니다. InstructGPT(Ouyang 외, 2022)가 이 방법으로 지시를 따르는 모델을 만들었습니다.
- [[DPO]](direct preference optimization)는 보상 모델과 강화 학습을 거치지 않습니다. 나은 답의 확률은 높이고 못한 답의 확률은 낮추도록 바로 학습시킵니다(Rafailov 외, 2023). 예제의 instruct 모델은 DPO에 15만 쌍을 쓰고, 그 뒤에 강화 학습을 더 했습니다(Qwen Team, 2024).

## 환각이 생기는 이유

:::요점
사전 학습은 그럴듯한 글이 나오도록 모델을 고칠 뿐, 사실인지 확인하는 단계가 없습니다. 그래서 틀린 문장도 그럴듯하면 높은 확률로 생성됩니다.
:::

[[환각]](hallucination)은 근거가 없는 내용을 사실처럼 생성하는 현상이고, 원인은 학습 목표에 있습니다. 사전 학습은 "실제로 이어진 토큰"의 확률을 높일 뿐, 내용이 사실인지는 따로 가르치지 않습니다. 그래서 드물게 나온 사실이나 학습하지 않은 내용 앞에서도 그럴듯한 말을 이어 씁니다.

:::예제 2-3 틀린 문장의 손실
베이스 모델로 맞는 문장, 낱말 하나만 바꾼 틀린 문장, 어순을 섞은 문장의 손실을 계산합니다. 손실이 낮을수록 모델이 그럴듯하다고 본다는 뜻입니다. 평균 손실은 토큰 수가 같은 문장끼리 비교해야 하므로 쌍마다 토큰 수를 같게 맞췄습니다. 틀린 문장의 손실이 더 높은지 봅니다.

```python
def sentence_loss(text):
    """위치마다 -log(실제 다음 토큰의 확률)을 구해 평균한 값"""
    input_ids = tokenizer(text, return_tensors='pt').input_ids
    with torch.no_grad():
        # labels를 넣으면 위치마다 실제 다음 토큰의 -log p를 구해 평균한 손실을 돌려줍니다
        return base_model(input_ids, labels=input_ids).loss.item()   # .item(): 파이썬 숫자로


sentences = [
    '다이싱은 웨이퍼를 개별 칩으로 자르는 공정입니다.',
    '다이싱은 웨이퍼를 개별 칩으로 붙이는 공정입니다.',
    '와이어 본딩은 칩과 리드를 금속선으로 잇는 공정입니다.',
    '와이어 본딩은 칩과 리드를 금속선으로 자르는 공정입니다.',
    '공정입니다 칩으로 웨이퍼를 다이싱은 개별 자르는.',
]
for sentence in sentences:
    print(f'손실 {sentence_loss(sentence):.2f}  {sentence}')
```
:::

틀린 문장의 손실은 맞는 문장보다 높지 않았고, 확실히 높은 것은 어순을 섞은 문장뿐입니다. 이 모델은 한국어로 자연스러운지는 구분하지만, 다이싱이 칩을 자르는지 붙이는지는 거의 구분하지 못합니다.

계산도 같은 이유로 틀릴 수 있습니다. 숫자도 토큰으로 나뉘어(1장) 다음 토큰 예측으로 답이 만들어지므로, 계산은 도구에 맡깁니다(13장).

## thinking 모델

:::요점
thinking 모델은 답하기 전에 문제를 푸는 토큰을 먼저 생성하도록, 정답을 확인할 수 있는 문제로 강화 학습한 모델입니다. 이 thinking 토큰도 출력 토큰이므로 화면에 보이지 않아도 시간과 요금이 듭니다.
:::

모델은 토큰 하나마다 정해진 층을 한 번씩 거칩니다(1장). 복잡한 문제의 답을 바로 쓰게 하면 답 토큰 하나에 그 한 번의 계산만 쓰는 셈입니다. [[thinking 모델]](reasoning model)은 답하기 전에 문제를 푸는 토큰(thinking 토큰)을 먼저 생성하는데, 이 과정을 [[thinking]]이라고 합니다. 답 토큰은 앞의 thinking 토큰을 입력으로 보고 계산됩니다(아래 그림).

:::예제 2-4 thinking 토큰
쉬운 질문과 조건이 얽힌 일정 문제(정답 "월-A, 화-D, 수-B, 목-C")를 보내 출력 토큰 수(`reply.output_tokens`), 걸린 시간(`reply.seconds`), 응답 글자 수를 비교합니다. 응답은 짧은데 출력 토큰이 많으면 그만큼 thinking에 쓴 것입니다. `max_tokens=8000`은 thinking이 잘리지 않게 넉넉히 둔 상한입니다. 사내 API의 모델이 thinking 모델이 아니면 두 질문의 차이가 작습니다. 이 셀은 API를 2번 호출합니다.

## 자가점검

**1.** 베이스 모델에 "다이싱이란 무엇입니까?"를 넣었더니 비슷한 질문을 여러 줄 이어 썼습니다. 사전 학습의 목표로 이 행동을 설명해 보세요.

:::정답
사전 학습은 글에서 실제로 이어진 다음 토큰을 맞히도록 학습합니다. 학습한 글에 FAQ 목록처럼 질문이 나열된 글이 있으면, 질문 다음에 다른 질문이 오는 이어짐도 그럴듯합니다. 베이스 모델은 "질문을 받으면 답한다"를 배운 적이 없고, 이 글이 이어질 법한 방향으로 쓴 것입니다.
:::

**2.** 어떤 위치에서 모델이 실제 다음 토큰에 0.5의 확률을 주었고, 다른 위치에서는 0.05를 주었습니다. 두 위치의 손실은 각각 얼마이고, 학습은 이 값을 어떻게 바꾸려 합니까?

:::정답
-log 0.5 ≈ 0.69, -log 0.05 ≈ 3.00입니다(자연로그). 학습은 손실이 줄어들도록, 즉 실제 다음 토큰의 확률이 높아지도록 파라미터를 고칩니다. 손실이 큰 둘째 위치를 학습이 더 크게 고칩니다.
:::

**3.** 다음 데이터는 각각 어느 학습 단계에 쓰입니까? (가) "질문: 와이어 본딩이란? 답: 칩과 리드를 금속선으로 잇는 공정입니다." (나) 한 질문에 대한 두 답과 "답 B가 낫다"는 표시 (다) 정답이 정해진 수학 문제 (라) 반도체 관련 웹 문서 수십억 건

:::정답
(가) SFT, (나) RLHF 또는 DPO, (다) thinking 모델의 강화 학습, (라) 사전 학습입니다.
:::

**4.** RLHF와 DPO는 같은 선호 데이터를 씁니다. 두 방법은 무엇이 다릅니까?

:::정답
RLHF는 선호 데이터로 보상 모델을 먼저 학습시키고, 모델이 생성한 답에 보상 모델이 점수를 매기게 해 강화 학습합니다. DPO는 보상 모델과 강화 학습 없이, 나은 답의 확률은 높이고 못한 답의 확률은 낮추도록 모델을 바로 학습시킵니다.
:::

**5.** 지난달 개정된 사내 규정을 모델에게 물었더니 그럴듯한 개정 내용을 답했습니다. 이 답을 믿으면 안 되는 이유를 두 가지 이상 들어 보세요.

:::정답
개정이 지식 기준일 뒤의 일이면 모델은 그 내용을 학습하지 않았습니다. 사내 규정은 기준일과 상관없이 학습한 글에 없습니다. 모델은 학습하지 않은 내용 앞에서도 그럴듯한 글을 이어 쓰도록 학습했으므로 환각이 생깁니다. 개정 문서를 입력에 넣어 그 문서를 근거로 답하게 해야 합니다.
:::

**6.** 교재의 실행에서 예제 2-3의 "다이싱은 웨이퍼를 개별 칩으로 붙이는 공정입니다"의 손실이 맞는 문장보다 낮았습니다. 이 결과가 환각에 대해 말해 주는 것은 무엇입니까?

:::정답
모델이 학습으로 배운 것은 글이 그럴듯하게 이어지는지이고, 사실인지가 아닙니다. 틀린 문장도 그럴듯하면 높은 확률로 생성될 수 있습니다. 큰 모델은 학습한 글에 많이 나온 사실은 잘 구분하지만, 학습한 글에 드문 사실 앞에서는 같은 문제가 생깁니다.
:::

**7.** thinking 모델로 짧은 답을 받았는데, 토큰 사용량을 보니 출력 토큰이 수천 개였습니다. 왜 그렇습니까? 이 점을 업무에 쓸 때 무엇을 고려해야 합니까?

:::정답
thinking 모델은 답하기 전에 thinking 토큰을 생성하고, 이 토큰은 응답에 보이지 않아도 출력 토큰으로 계산됩니다. 출력 토큰은 단가가 높고 생성 시간도 걸리므로, 단순한 작업에는 thinking을 적게 쓰게 하고 판단이 필요한 작업에만 많이 쓰게 하는 것을 고려합니다(5장의 effort).
:::
