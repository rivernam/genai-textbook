11장 파인튜닝

강의 6일차 파트 1과 파트 3에 해당합니다.

프롬프트와 RAG(retrieval-augmented generation)는 모델에 보내는 입력을 바꿉니다. 파인튜닝은 모델의 파라미터 자체를 바꿉니다. 이 장은 언제 파라미터를 바꿔야 하는지, 학습이 파라미터를 어떻게 고치는지, 적은 메모리로 고치는 방법인 LoRA(low-rank adaptation)가 어떻게 동작하는지, 학습한 모델에서 무엇을 점검해야 하는지를 설명합니다.

학습 목표

  1. 프롬프트, RAG, 파인튜닝이 각각 무엇을 바꾸는지 설명하고, 모델이 모르는 사실이 문제인지 형식과 판단 기준을 따르지 않는 것이 문제인지로 셋 중 하나를 고를 수 있습니다.
  2. 학습 데이터가 채팅 템플릿, 최대 길이, 패딩을 거쳐 배치가 되고, 손실은 답 부분에서만 계산된다는 것을 설명할 수 있습니다.
  3. 경사 하강법이 파라미터를 고치는 과정과 학습률, 배치, 에포크의 뜻을 설명하고, 학습 데이터와 평가셋의 결과로 과적합을 알아볼 수 있습니다.
  4. LoRA가 원래 행렬을 고정하고 작은 행렬 두 개만 학습하는 원리를 설명하고, 학습하는 파라미터 수를 계산할 수 있습니다.
  5. 파인튜닝한 모델을 평가셋, 망각, 환각의 세 가지로 점검하고, 파인튜닝해도 환각이 없어지지 않는 이유를 설명할 수 있습니다.

예제 11-1~11-3과 실습 11-1, 11-2는 PC의 CPU(central processing unit)에서 1장의 공개 LLM(large language model)인 Qwen2.5-0.5B-Instruct를 학습하고 실행합니다. 예제 11-3의 학습은 몇 분 걸립니다. 실습 11-3은 GPU(graphics processing unit)가 있는 환경에서 실행합니다. 이 장은 준비 셀의 연결 확인 말고는 API(application programming interface)를 호출하지 않습니다. 손실, 걸린 시간, 학습한 모델의 답은 PC, 라이브러리 버전, 실행할 때마다 교재와 다를 수 있습니다.

프롬프트, RAG, 파인튜닝

프롬프트와 RAG는 요청마다 보내는 입력을 바꾸고, 파인튜닝은 모델의 파라미터를 바꿉니다. 모델이 모르는 사실이 필요하면 RAG를, 프롬프트에 적어도 형식이나 판단 기준을 지키지 않으면 파인튜닝을 검토합니다.

파인튜닝(fine-tuning)은 사전 학습을 마친 모델을 특정한 목적의 데이터로 더 학습시키는 것입니다. 방법은 2장의 SFT(supervised fine-tuning)와 같습니다. 입력과 모범 답의 쌍을 넣고, 모범 답에 높은 확률을 주도록 파라미터를 고칩니다. SFT와 다른 것은 데이터입니다. 모델 회사는 온갖 주제의 대화로 학습시키고, 파인튜닝은 우리 업무의 입력과 답으로 학습시킵니다.

세 방법 가운데 무엇을 쓸지는 지금 겪는 문제가 무엇인지로 정합니다.

  • 지시를 프롬프트에 적어서 원하는 결과가 나오면 프롬프트로 끝냅니다. 학습 데이터를 만들 필요도, 학습한 모델을 따로 운영할 필요도 없습니다.
  • 모델이 모르는 사실(사내 기준값, 최근 개정 내용)이 필요하면 RAG를 씁니다. 사실은 문서에 있으므로, 문서가 바뀌면 인덱스만 다시 만들면 됩니다. 사실을 파인튜닝으로 넣으면 문서가 바뀔 때마다 다시 학습해야 하고, 학습한 사실을 모델이 정확히 꺼낸다는 보장도 없습니다("학습한 모델에서 점검할 것" 절).
  • 프롬프트에 규칙을 적어도 모델이 형식이나 판단 기준을 지키지 않으면 파인튜닝을 검토합니다. 사내 표준 형식, 글로 다 적기 어려운 분류 기준, 정해진 말투가 여기에 해당합니다. 이런 것은 규칙을 글로 설명하는 것보다 입력과 답의 예 수십~수백 건으로 보여 주는 편이 모델에 잘 전달됩니다.
  • 요청마다 긴 지시와 예시를 넣고 있으면 파인튜닝으로 그 입력을 줄일 수 있습니다. 작은 모델을 파인튜닝해 큰 모델 대신 쓰면 비용도 줄어듭니다(12장).

두 방법을 함께 쓸 수도 있습니다. 사실은 RAG로 찾아 넣고, 답하는 형식은 파인튜닝으로 익히게 하는 구성입니다.

이 장의 예제는 설비 알람을 사내 표준 형식 "설비코드 | 분류 | 담당"으로 바꾸는 과제를 씁니다. 예를 들어 "3호기 와이어 본더 본딩 강도 기준 미달 로트 발생"은 "WB-03 | 품질 | 품질팀"이 됩니다. 설비코드는 설비 종류의 약어(와이어 본더는 WB)에 호기를 붙인 것이고, 분류는 안전, 품질, 설비 중 하나이며, 담당은 분류에 따라 정해집니다. 모델이 모르는 사실이 아니라 회사가 정한 형식과 기준을 따르는 과제이므로 파인튜닝을 검토할 만한 과제입니다. 알람은 학습 데이터 64건과 평가셋 32건으로 나눠 두었습니다(노트북/data/알람.csv).

학습 데이터가 배치가 되기까지

학습 데이터 한 건은 채팅 템플릿을 거쳐 토큰 ID의 나열이 됩니다. 여러 건을 한 번에 계산하려고 패딩으로 길이를 맞추고, 손실은 모델이 생성해야 할 답 부분에서만 계산합니다.

학습 데이터 한 건은 알람(입력)과 표준 형식(모범 답)의 쌍입니다. 모델이 받는 것은 토큰 ID의 나열 하나뿐이므로, 학습 코드는 이 쌍을 다음 순서로 바꿉니다.

  1. 채팅 템플릿(3장)으로 시스템 프롬프트, 알람, 답을 글 한 덩어리로 잇습니다. 학습한 모델을 쓸 때도 같은 템플릿으로 입력해야 합니다. 템플릿이 다르면 모델이 학습한 형식과 실제 입력이 달라 학습한 대로 답하지 않습니다.
  2. 토크나이저로 토큰 ID의 나열로 바꿉니다. 이때 최대 길이(max length)를 넘는 뒤쪽은 잘라 냅니다. 학습에 드는 메모리와 시간은 토큰 수에 따라 늘어나므로 상한을 둡니다.
  3. 여러 건을 묶어 한 번에 계산합니다. 묶은 단위를 배치(batch)라고 합니다. 배치는 행렬 하나로 계산하므로 모든 행의 길이가 같아야 합니다. 그래서 짧은 행의 뒤에 패딩(padding) 토큰을 채웁니다. 함께 만드는 어텐션 마스크(attention mask)는 위치마다 실제 토큰이면 1, 패딩이면 0이고, 모델은 0인 위치를 계산에 쓰지 않습니다.
  4. 손실을 계산할 위치를 정합니다. 위치마다 정답 토큰을 적은 목록(labels)에서 프롬프트와 패딩 위치는 -100으로 바꿉니다. -100인 위치는 손실 계산에서 빠집니다.

손실을 답 부분에서만 계산하는 이유는 가르치려는 것이 "알람이 주어지면 표준 형식으로 답하기"이기 때문입니다. 프롬프트까지 손실에 넣으면 모델은 시스템 프롬프트와 알람 글을 이어 쓰는 법도 함께 학습합니다. 최대 길이가 프롬프트보다 짧으면 답이 모두 잘려 손실을 계산할 위치가 하나도 남지 않으므로, 최대 길이는 가장 긴 학습 데이터의 토큰 수를 세어 정합니다.

예제 11-1패딩과 손실을 계산하는 위치노트북 11_파인튜닝.ipynb의 예제 11-1

학습 데이터 세 건을 배치 하나로 만들고, 건마다 실제 토큰, 패딩, 손실을 계산하는 토큰의 개수와 손실을 계산하는 부분의 글을 출력합니다. 마지막 줄에서는 최대 길이를 40토큰으로 줄였을 때 손실을 계산하는 부분에 무엇이 남는지 봅니다. make_batch()는 준비 셀에 있는 함수로, 이 절의 네 단계를 실행합니다.

batch = make_batch(train_rows[:3])                  # 학습 데이터 3건을 배치 하나로 만듭니다
print('배치의 크기(건수, 토큰 수):', tuple(batch['input_ids'].shape))
for row, ids, mask, labels in zip(train_rows[:3], batch['input_ids'], batch['attention_mask'], batch['labels']):
    real, padding, scored = int(mask.sum()), int((mask == 0).sum()), int((labels != -100).sum())
    print(f"\n{row['알람']}\n  실제 토큰 {real}개, 패딩 {padding}개, 손실을 계산하는 토큰 {scored}개")
    print('  마지막 6토큰:', repr(tokenizer.decode(ids[-6:])))
    print('  손실을 계산하는 부분:', repr(tokenizer.decode(labels[labels != -100])))

short = make_batch(train_rows[:1], max_length=40)   # 최대 길이를 40토큰으로 줄이면
labels = short['labels'][0]
print('\n최대 길이 40토큰일 때 손실을 계산하는 부분:', repr(tokenizer.decode(labels[labels != -100])))

경사 하강법과 학습률

경사 하강법은 파라미터마다 기울기를 구하고, 기울기의 반대 방향으로 학습률만큼 파라미터를 옮기는 일을 되풀이합니다. 학습률이 너무 작으면 손실이 거의 줄지 않고, 너무 크면 최솟값을 지나쳐 손실이 오히려 커집니다.

2장에서 학습은 손실이 줄어드는 방향으로 파라미터를 조금씩 고치는 일이라고 했습니다. 그 방향을 정하는 값이 기울기(gradient)입니다. 기울기는 파라미터 하나를 아주 조금 늘렸을 때 손실이 얼마나 늘거나 주는지를 나타냅니다. 기울기가 음수면 파라미터를 늘릴 때 손실이 줄고, 양수면 파라미터를 줄일 때 손실이 줍니다. 그래서 경사 하강법(gradient descent)은 파라미터에서 기울기에 학습률(learning rate)을 곱한 만큼을 뺍니다.

새 파라미터 = 파라미터 - 학습률 × 기울기

파라미터가 w 하나이고 손실이 (w - 3)²인 문제로 계산해 보면 다음과 같습니다. 손실이 가장 작은 곳은 w=3입니다. w=0에서 손실은 9이고, 기울기는 2 × (0 - 3) = -6입니다. 학습률이 0.1이면 w는 0 - 0.1 × (-6) = 0.6이 되고 손실은 5.76으로 줄어듭니다. 이 한 번의 수정을 스텝(step)이라고 합니다.

실제 모델의 파라미터는 수억 개이고, 손실은 그 전부에 걸린 함수입니다. 학습 코드는 손실을 계산한 뒤 loss.backward()를 호출해 모든 파라미터의 기울기를 한 번에 구합니다. 출력 쪽 층에서 입력 쪽 층으로 거슬러 가며 미분을 계산하므로 이 계산을 역전파(backpropagation)라고 합니다. 이어서 옵티마이저(optimizer)가 기울기로 파라미터를 고칩니다. 예제가 쓰는 AdamW는 파라미터마다 최근 기울기의 평균과 크기를 기억해 두고 스텝의 폭을 파라미터마다 조절하는 옵티마이저이며, 학습률은 그 폭 전체의 크기를 정합니다.

학습률은 사람이 정하는 값입니다. 너무 작으면 스텝마다 조금씩만 움직여 같은 횟수를 학습해도 손실이 거의 줄지 않습니다. 너무 크면 최솟값을 지나쳐 반대편으로 넘어가고, 넘어간 거리가 처음보다 멀면 스텝마다 손실이 커집니다. 학습 중에 손실이 오르내리거나 갑자기 커지면 학습률을 의심합니다. 여러 학습률의 결과는 실습 11-1에서 계산합니다.

배치, 에포크, 과적합

배치 하나로 파라미터를 한 번 고치는 것이 스텝이고, 학습 데이터 전체를 한 번 다 쓰는 것이 에포크입니다. 학습 데이터의 손실만 보면 과적합을 알 수 없으므로, 학습에 쓰지 않은 평가셋으로 함께 측정합니다.

기울기는 배치 하나의 평균 손실로 계산합니다. 한 건씩 고치면 그 건에만 맞춰 방향이 매번 바뀌고, 데이터 전체로 한 번에 계산하면 메모리가 부족하기 때문입니다. 배치가 클수록 기울기가 안정되지만 메모리가 더 듭니다. 학습 데이터 전체를 한 번 다 쓰는 단위를 에포크(epoch)라고 합니다.

에포크를 늘리면 학습 데이터의 손실은 계속 내려갑니다. 그러다 모델이 학습 데이터의 문장 자체를 외우기 시작하면, 처음 보는 입력에서는 오히려 결과가 나빠집니다. 이 상태를 과적합(overfitting)이라고 합니다. 2장의 예제 2-1에서 문장 30개로 1,000번 학습한 작은 모델이 학습한 문장을 거의 그대로 외운 것도 과적합입니다.

과적합은 학습 데이터만으로는 알 수 없습니다. 그래서 학습을 시작하기 전에 데이터의 일부를 평가셋(evaluation set)으로 떼어 두고, 학습에는 쓰지 않습니다. 평가셋의 손실이나 정확도가 좋아지다가 나빠지기 시작하면 그 앞에서 학습을 멈추고, 학습 데이터를 늘리거나 에포크를 줄입니다.

전체 파인튜닝과 LoRA

전체 파인튜닝은 모든 파라미터를 고치므로 기울기와 옵티마이저 상태까지 파라미터 수만큼 메모리가 듭니다. LoRA는 원래 행렬을 고정하고 옆에 붙인 작은 행렬 두 개만 학습해, 학습하는 파라미터를 1% 아래로 줄입니다.

모든 파라미터를 고치는 전체 파인튜닝(full fine-tuning)은 파라미터마다 기울기와 옵티마이저 상태(AdamW는 값 두 개)를 메모리에 둡니다. 파라미터 70억 개 모델이면 이것만으로 GPU 한 장의 메모리를 넘습니다(12장에서 계산합니다). 학습이 끝나면 모델 전체의 사본이 하나 생기므로, 과제가 열 개면 사본도 열 개입니다.

LoRA(low-rank adaptation)는 원래 행렬 W를 고정하고, 옆에 작은 행렬 두 개 A와 B를 붙여 그것만 학습합니다(Hu 외, 2021). W가 d × k 행렬일 때 A는 r × k, B는 d × r이고, 둘을 곱한 BA는 W와 크기가 같은 d × k 행렬입니다. r을 rank라고 하며 보통 4~64로 작게 둡니다. 출력은 원래 행렬의 결과에 BA의 결과를 더한 것입니다. 더할 때 곱하는 α / r에서 α(lora_alpha)는 BA의 효과를 얼마나 크게 반영할지 정하는 값입니다.

이 방식이 통하는 이유와 특징은 다음과 같습니다.

  • BA는 크기가 W와 같지만 rank가 r 이하인 행렬이므로, LoRA는 W에 더할 변화를 이런 단순한 행렬로 제한합니다. Hu 외(2021)는 GPT-3 175B에서 r을 1~8 정도로 작게 두어도 전체 파인튜닝과 비슷하거나 나은 성능이 나왔고, 학습하는 파라미터는 1만분의 1로, 학습에 필요한 GPU 메모리는 3분의 1로 줄었다고 보고했습니다. 파인튜닝으로 생기는 변화가 그만큼 단순한 경우가 많다는 뜻입니다.
  • B를 0으로 시작하므로 학습 전에는 BA가 0이고, 모델의 출력이 원래 모델과 같습니다. 학습은 원래 모델에서 출발합니다.
  • 학습한 A와 B만 따로 저장한 파일을 어댑터(adapter)라고 합니다. 원래 모델 하나에 과제마다 어댑터를 바꿔 붙일 수 있고, 어댑터를 떼면 원래 모델로 돌아갑니다.
  • 학습한 뒤 BA를 W에 더해 행렬 하나로 합치면 생성 속도가 원래 모델과 같습니다(Hu 외, 2021).
  • Biderman 외(2024)는 같은 과제에서 LoRA가 전체 파인튜닝보다 목표 과제를 덜 학습하는 대신, 학습하지 않은 과제의 능력을 덜 잃었다고 보고했습니다. 잃는 능력은 "학습한 모델에서 점검할 것" 절에서 다룹니다.

LoRA처럼 파라미터의 일부만 학습하는 방법을 묶어 PEFT(parameter-efficient fine-tuning)라고 부르며, Hugging Face의 peft 라이브러리가 이런 방법들을 구현합니다.

예제 11-2LoRA가 학습하는 파라미터 수노트북 11_파인튜닝.ipynb의 예제 11-2

0번 층 어텐션의 q_proj 행렬 하나에 rank를 바꿔 LoRA를 붙일 때 학습하는 값의 수를 계산하고, 24개 층의 q_proj와 v_proj에 r=8로 LoRA를 붙인 모델에서 학습하는 파라미터의 비율을 셉니다. 행렬이 클수록 LoRA가 학습하는 비율이 작아지는 것을 봅니다.

from peft import LoraConfig, get_peft_model

q_proj = model.model.layers[0].self_attn.q_proj     # 0번 층 어텐션의 행렬 하나
d_out, d_in = q_proj.weight.shape
print(f'q_proj 행렬 {d_out}×{d_in}: {q_proj.weight.numel():,}개')
for rank in [1, 8, 64]:
    lora_count = rank * (d_out + d_in)              # B(d_out×r)와 A(r×d_in)의 값의 수
    print(f'  r={rank}: B와 A {lora_count:,}개 ({lora_count / q_proj.weight.numel():.1%})')

# target_modules: LoRA를 붙일 행렬의 이름. 24개 층마다 q_proj와 v_proj에 붙입니다
config = LoraConfig(r=8, lora_alpha=16, target_modules=['q_proj', 'v_proj'], task_type='CAUSAL_LM')
lora_model = get_peft_model(model, config)          # 원래 파라미터는 고정하고 LoRA 행렬만 학습 대상으로 둡니다
trainable = sum(p.numel() for p in lora_model.parameters() if p.requires_grad)
total = sum(p.numel() for p in lora_model.parameters())
print(f'\n학습하는 파라미터 {trainable:,}개 / 전체 {total:,}개 = {trainable / total:.2%}')

학습한 모델에서 점검할 것

학습한 모델은 평가셋의 정확도, 학습과 무관한 질문에서 잃은 능력(망각), 모르는 것을 지어내는지(환각)의 세 가지로 점검합니다. 파인튜닝은 답하는 형식과 기준을 바꾸지만, 모델이 사실을 확인하게 만들지는 않습니다.

평가셋

학습 손실이 낮아도 처음 보는 입력에서 맞히는지는 알 수 없습니다. 학습에 쓰지 않은 평가셋으로 학습 전후의 정확도를 측정하고, 학습 전 모델은 규칙을 다 적은 프롬프트로 측정해 "프롬프트로 충분한가"와 비교합니다(실습 11-2). 평균 정확도만 보지 않고, 학습 전에는 맞히다가 학습 후에 틀린 건이 있는지도 봅니다.

망각

새 과제를 학습하면서 원래 하던 일을 못 하게 되는 현상을 망각(catastrophic forgetting)이라고 합니다. 파인튜닝은 학습 데이터에 대한 손실만 줄이도록 파라미터를 고치고, 학습 데이터에 없는 일을 그대로 유지하라는 신호는 주지 않기 때문입니다. 학습 데이터가 한 가지 과제뿐이면, 모델은 어떤 입력에도 그 과제의 형식으로 답하는 쪽으로 학습될 수 있습니다. 학습과 무관한 질문 몇 개를 정해 두고 학습 전후의 답을 비교하면 망각을 확인할 수 있습니다. LoRA는 어댑터를 떼면 원래 모델로 돌아가므로, 같은 모델에서 전후를 바로 비교할 수 있습니다(실습 11-2).

환각

파인튜닝으로 사실을 가르치면 모델이 그 사실을 믿을 만하게 답할 것 같지만, 그렇지 않습니다. Gekhman 외(2024)는 모델이 사전 학습에서 몰랐던 사실을 파인튜닝으로 학습시키는 실험에서, 모델이 그런 예를 이미 알던 사실보다 느리게 학습했고, 그런 예를 학습할수록 환각이 늘었다고 보고했습니다. 저자들은 모델이 사실을 주로 사전 학습에서 익히고, 파인튜닝에서는 이미 아는 것을 쓰는 방법을 익힌다고 해석했습니다. 모르던 사실을 억지로 학습시키면 자기 지식에 근거하지 않은 답을 생성하는 법도 함께 학습한다는 것입니다.

2장에서 설명한 환각의 원인도 파인튜닝으로 사라지지 않습니다. 학습 목표는 여전히 모범 답의 토큰에 높은 확률을 주는 것이고, 모델이 답하기 전에 사실을 확인하는 단계는 생기지 않습니다. 그래서 문서에 있는 사실은 RAG로 찾아 넣고 근거를 표시하게 하며, 파인튜닝은 형식과 기준을 익히는 데 씁니다.

def descend(learning_rate, steps=5, w=0.0):
    """손실 (w - 3)²에 경사 하강법을 steps번 적용하고, 스텝마다의 w를 목록으로 돌려줍니다"""
    history = [w]
    for _ in range(steps):
        gradient = 2 * (w - 3)
        w = w - learning_rate * gradient
        history.append(w)
    return history
