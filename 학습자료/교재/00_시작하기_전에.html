시작하기 전에

강의 1~3일차의 환경 준비에 해당합니다.

이 장은 교재를 읽는 방법과, 예제와 실습을 직접 실행하는 데 필요한 준비를 설명합니다. 읽기만 한다면 첫 절 "교재와 노트북"만 읽고 1장으로 넘어가도 됩니다. 직접 실행하려면 "준비물"부터 "연결 확인"까지를 한 번 따라 합니다. PC에서 모델을 실행하는 장은 "장마다 더 필요한 것"도 봅니다.

교재와 노트북

교재에는 설명, 예제 코드와 실행 결과, 실습 풀이가 모두 있어 읽기만 해도 됩니다. 직접 실행하려면 장마다 이름이 같은 장 노트북을 열고, 관통 프로젝트는 프로젝트 노트북을 엽니다.

교재는 6부 15장입니다. 1부에서 LLM(large language model)이 토큰을 확률로 골라 글을 만드는 원리와 컨텍스트를 설명하고, 2부부터는 프롬프트, API(application programming interface), 검색, 파인튜닝, 에이전트, 보안을 차례로 다룹니다. 뒤의 장은 1부의 원리로 현상을 설명하므로 1부를 먼저 읽기를 권합니다.

장은 학습 목표, 본문, 개념 확인 실습, 자가점검 순서로 되어 있습니다. 본문의 각 절은 그 절의 결론을 한두 문장으로 줄인 요점 상자로 시작합니다.

  • 예제는 직접 실행해야 납득되는 현상만 보여 줍니다. 장마다 2~4개입니다. 예제 상자의 코드는 장 노트북의 코드 셀과 같고, 교재에는 그 코드를 실제로 실행한 결과가 함께 실려 있습니다.
  • 개념 확인 실습은 결과를 먼저 예측해 적고, 실행해서 확인하고, 예측과 다른 부분을 그 장의 원리로 설명하는 실습입니다. 장 노트북에는 빈칸이 있는 코드가 있고, 풀이는 교재에만 접혀 있습니다.
  • 관통 프로젝트는 여러 장에 걸쳐 "사내 문서 질의응답 도우미"를 한 단계씩 만드는 실습입니다. K단계의 프로젝트 노트북(프로젝트_K.ipynb)은 앞 단계들의 풀이 코드에서 시작합니다.

예제와 실습의 재료(문의, 사내 문서, 설비 알람 기록 등)는 가상의 반도체 후공정 회사를 배경으로 직접 작성한 것입니다. 설비 번호, 관리 기준값, 담당 부서 같은 회사 고유 정보는 가상이고, 공정에 관한 일반 설명은 널리 알려진 내용입니다. 재료는 노트북 폴더의 data 아래에 있고, 구성은 data/README.md에 있습니다.

준비물

Python 3.10 이상과 Jupyter, 노트북 폴더, LLM API의 키(사내 API라면 주소와 모델 이름도)가 필요합니다. 1~3장과 6~14장은 PC에서 모델이나 토크나이저를 실행하므로 패키지를 더 설치하고 모델 파일을 내려받습니다.

노트북은 사내 PC의 Jupyter나 VS Code의 노트북 화면에서 실행합니다. 노트북 폴더에는 다음 파일이 있습니다. 노트북은 반드시 이 폴더에서 엽니다. 노트북이 같은 폴더의 파일을 불러오기 때문입니다.

  • NN_장제목.ipynb는 장 노트북입니다. 준비 셀, 예제 셀, 개념 확인 실습의 빈칸 셀이 들어 있습니다.
  • 프로젝트_K.ipynb는 관통 프로젝트 K단계 노트북입니다. 앞 단계 풀이의 첫 셀(뒤 단계가 쓰는 함수)과 K단계의 빈칸이 들어 있습니다.
  • llm.py는 LLM API를 호출하는 공통 함수를 모은 파일입니다. Anthropic API와 OpenAI 호환 API(사내 API)를 같은 함수로 호출합니다.
  • embed.py는 임베딩 모델을 불러오는 함수(7장부터)와, PC에서 실행할 모델을 내려받을 주소를 묻는 함수를 모은 파일입니다.
  • corpus.py는 사내 문서 120건을 읽고 검색하는 함수를 모은 파일입니다(7~9장).
  • doc_tools.py는 에이전트가 쓰는 문서 검색과 읽기 도구를 모은 파일입니다(13장).
  • data 폴더에는 예제와 실습의 재료가 있습니다.

모든 장에 필요한 패키지는 다음 명령으로 설치합니다.

python -m pip install anthropic openai pandas pydantic openpyxl jupyter

API 키 다루기

API 키는 코드나 노트북에 적지 않고 환경 변수에 둡니다. 키가 든 파일을 공유하면 키도 함께 퍼지고, 그 키로 보낸 요청의 요금은 키 주인에게 청구됩니다.

API 키(API key)는 API를 호출한 사람을 식별하는 문자열입니다. 사용 기록과 요금은 키별로 집계됩니다. 키를 가진 사람은 누구나 그 키로 호출할 수 있으므로, 코드에 적은 키는 파일을 공유하거나 저장소에 올리는 순간 다른 사람도 쓸 수 있습니다.

그래서 키는 환경 변수(environment variable)에 두고 코드에서는 환경 변수를 읽습니다. 환경 변수는 운영체제가 프로그램에 넘겨주는 이름과 값의 쌍입니다. 이 교재의 노트북과 llm.py에는 키, 사내 주소, 사내 모델 이름이 적혀 있지 않습니다.

키를 메신저, 화면 공유, 캡처 이미지에 노출하지 않습니다. 노출됐다면 바로 폐기하고 새로 발급받습니다.

환경 변수 설정

llm.py는 환경 변수 LLM_PROVIDER를 보고 Anthropic API와 사내 API 가운데 어디로 요청을 보낼지 고릅니다. 환경 변수는 Jupyter를 시작하기 전에 설정합니다.

교재의 예제는 모델 이름 대신 소형, 기본, 대형의 세 모델 등급(model tier)으로 모델을 고릅니다. 모델 등급은 같은 제공사의 모델을 능력과 가격으로 나눈 구분입니다(5장 "모델 등급 고르기"). 실제 모델 이름은 환경 변수로 연결합니다.

환경 변수 값
ANTHROPIC_API_KEY 발급받은 키

모델 이름은 설정하지 않아도 됩니다. llm.py에 소형 claude-haiku-5-5, 기본 claude-sonnet-5-5, 대형 claude-opus-5-5가 들어 있습니다(2026-11 확인).

환경 변수 값
LLM_PROVIDER openai
OPENAI_BASE_URL 사내 API 주소. 보통 /v1로 끝납니다
OPENAI_API_KEY 사내 API 키
LLM_MODEL_SMALL 소형 모델 이름
LLM_MODEL_DEFAULT 기본 모델 이름
LLM_MODEL_LARGE 대형 모델 이름
LLM_STRUCTURED 구조화 출력을 요청하는 방식. 설정하지 않으면 json_schema입니다. 서버가 이 방식을 지원하지 않을 때만 바꿉니다(6장 "구조화 출력")

사내에서 쓸 수 있는 모델이 하나뿐이면 세 변수에 같은 이름을 넣습니다. 그러면 모델 등급을 비교하는 예제와 실습에서는 등급 사이의 차이가 나오지 않습니다.

Windows PowerShell에서는 setx로 설정합니다. setx로 설정한 값은 그 뒤에 새로 연 창에만 적용되므로, 설정한 뒤 터미널을 새로 열고 그 터미널에서 Jupyter를 시작합니다. VS Code로 노트북을 연다면 VS Code 창을 모두 닫았다가 다시 엽니다. setx로 설정한 값은 모든 장의 노트북에 그대로 적용됩니다.

Anthropic API를 쓸 때:

setx ANTHROPIC_API_KEY "발급받은_키"

사내 API를 쓸 때(위 표의 나머지 변수도 같은 방법으로 설정합니다):

setx LLM_PROVIDER openai
setx OPENAI_BASE_URL "사내_API_주소"
setx OPENAI_API_KEY "사내_API_키"

환경 변수를 미리 설정하지 못했다면 노트북의 "준비 (1)" 셀이 키, 주소, 모델 이름을 물어봅니다. 입력한 값은 화면에 보이지 않고 노트북 파일에도 저장되지 않습니다. 이 값은 커널이 살아 있는 동안만 쓰이므로, 노트북을 새로 열거나 커널을 다시 시작하면 다시 입력합니다. 단, 사내 API를 쓰려면 LLM_PROVIDER=openai만은 Jupyter를 시작하기 전에 설정해야 합니다. "준비 (1)" 셀이 이 값을 보고 어떤 값을 물을지 정하기 때문입니다. 이 값이 없으면 llm.py는 Anthropic API로 요청을 보냅니다.

연결 확인

노트북 첫머리의 "준비 (1)", "준비 (2)" 셀을 차례로 실행해 마지막 줄에 모델의 응답이 나오면 연결된 것입니다. 오류가 나면 오류 문구로 원인을 찾습니다.

어느 장의 노트북이든 노트북 폴더에서 열고 "준비 (1)", "준비 (2)" 셀을 차례로 실행합니다. "준비 (2)" 셀은 세 모델 등급의 실제 모델 이름을 출력하고, 소형 모델에 요청 하나를 보냅니다. 두 셀이 오류 없이 끝나고 마지막 줄에 모델의 응답(보통 준비 완료)이 나오면 연결된 것입니다. 응답 문구는 모델에 따라 조금 다를 수 있습니다.

오류가 나면 아래 표에서 원인을 찾습니다.

준비 셀이 정의하는 이름

"준비 (1)", "준비 (2)" 셀은 예제가 공통으로 쓰는 이름을 정의합니다. 예제 코드에 정의 없이 나오는 이름은 이 두 셀에서 정의한 것입니다.

  • llm은 공통 호출 함수가 든 모듈(llm.py)입니다. 예제는 API를 이 모듈로만 호출합니다.
  • os, json, time, pd(pandas), ThreadPoolExecutor는 파이썬 표준 라이브러리와 pandas입니다.
  • DATA는 재료 폴더의 경로(data)입니다.
  • 장마다 필요한 재료 읽기, 단가표, PC 모델 불러오기는 "준비 (2)" 셀의 중간에 그 장의 준비 코드로 들어 있습니다. 어떤 이름이 정의되는지는 그 셀에서 확인합니다.

장마다 더 필요한 것

몇몇 장은 PC에서 공개 모델이나 임베딩 모델을 실행하므로, 패키지를 더 설치하고 처음 한 번 모델 파일을 내려받습니다. 사내에서는 사내 Hugging Face 프록시에서 내려받습니다.

Anthropic API는 토큰마다의 확률을 돌려주지 않고, 어느 API도 모델 내부의 계산이나 학습 과정은 보여 주지 않습니다. 그래서 확률과 학습을 다루는 1, 2, 6, 11, 12장의 일부 예제는 공개 LLM인 Qwen2.5-0.5B-Instruct(파라미터 약 5억 개)를 PC에서 실행합니다. 3, 13, 14장은 토큰 수를 세는 데 그 모델의 토크나이저(1장)만 씁니다. 7~10장은 임베딩 모델(embedding model)을 PC에서 실행합니다(7장). 장 노트북의 "준비 (2)" 셀 안에 # 설치:로 시작하는 주석이 있으면 그 명령을 터미널에서 실행하고 커널을 다시 시작합니다.

모델 파일은 처음 불러올 때 한 번 내려받고, 그 뒤에는 PC에 저장된 파일을 씁니다. 사내에서는 Hugging Face에 직접 연결하지 않고 사내 Hugging Face 프록시에서 내려받습니다. 프록시 주소는 사내 안내에서 확인해 아래 환경 변수에 넣습니다. 이 교재에는 주소를 적지 않습니다.

환경 변수 값
HF_ENDPOINT 사내 Hugging Face 프록시 주소. https://로 시작하는 주소 전체를 넣습니다. 설정하지 않으면 huggingface.co에서 받습니다. 이 값도 Jupyter를 시작하기 전에 설정합니다
EMBED_MODEL 설정하지 않아도 됩니다. 다른 임베딩 모델을 쓰거나 모델 파일이 든 폴더를 따로 받았을 때, 모델 이름이나 폴더 경로를 넣습니다

모델이 PC에 없고 HF_ENDPOINT도 설정하지 않았으면, 모델을 처음 불러오는 셀이 프록시 주소를 물어봅니다. 임베딩 모델을 불러올 때 오류가 나면 오류 문구로 원인을 찾습니다.

  • "임베딩 모델 ...을 내려받지 못했습니다"는 프록시 주소가 틀렸거나 사내망에 연결되지 않은 경우입니다. HF_ENDPOINT의 값을 확인하고 Jupyter를 다시 시작합니다.
  • "HF_ENDPOINT는 Jupyter를 시작하기 전에 설정해야 합니다"는 같은 커널에서 Hugging Face 라이브러리를 이미 불러온 뒤에 주소를 입력한 경우입니다. 라이브러리는 처음 불러올 때 읽은 주소만 씁니다. 환경 변수 HF_ENDPOINT를 설정하고 Jupyter를 다시 시작합니다.
  • "sentence-transformers 패키지가 없습니다"는 패키지를 설치하지 않은 경우입니다. 위 표의 설치 명령을 실행한 뒤 커널을 다시 시작합니다.

공개 LLM이나 리랭커를 내려받지 못하면 OSError가 납니다. 조치는 임베딩 모델을 내려받지 못했을 때와 같습니다.

프로젝트 노트북은 그 단계까지 쓰는 장과 같은 패키지가 필요합니다. 예를 들어 프로젝트_6.ipynb는 5단계의 문서 도구를 쓰므로 13장과 같이 pypdf beautifulsoup4를 설치합니다.

사내 API로 실행할 때 확인할 것

사내 API(OpenAI 호환)로도 대부분의 예제와 실습을 실행할 수 있습니다. 다음 예제와 실습은 서버나 PC가 기능을 지원해야 실행됩니다.

  • 6장부터 schema=로 구조화 출력을 요청하는 예제와 실습은 사내 API가 json_schema 방식을 지원해야 그대로 실행됩니다. 지원하지 않으면 LLM_STRUCTURED를 바꿉니다(6장 "구조화 출력").
  • 13장의 예제 13-2, 13-3, 실습 13-1, 13-2, 관통 프로젝트 5, 6단계는 도구 호출(tool use)을 씁니다. 사내 API가 요청의 tools와 응답의 tool_calls를 지원해야 합니다.
  • 5장의 토큰 세기(llm.count_tokens())는 Anthropic API에서만 토큰 수를 돌려주고, 사내 API에서는 None을 돌려줍니다. 예제 5-1의 effort 비교도 Anthropic API에서만 실행됩니다.
  • 11장의 실습 11-3은 GPU(graphics processing unit)가 있는 환경에서 실행합니다. GPU 환경에서 노트북을 여는 방법은 사내 안내를 따릅니다.
  • 14장의 예제 14-1은 Claude Code가 설치되어 있고 로그인된 PC에서만 실행됩니다. 없으면 셀이 안내문만 출력합니다.

대부분의 예제와 실습 상자에는 그 셀이 API를 몇 번 호출하는지 적어 두었습니다. 교재의 예제와 실습은 대부분 소형 모델을 씁니다. 교재에 실린 실행 결과는 Anthropic API로 실행한 것이고, 모델의 응답과 소수점 아래 숫자는 PC, 라이브러리 버전, 실행할 때마다 교재와 다를 수 있습니다.
