# 용어집

교재 전체에서 쓰는 용어의 표기와 정의다. 원고의 `[[용어]]`는 이 표의 "용어" 열과 정확히 같아야 한다.
새 장을 쓸 때는 원고를 쓰기 전에 이 표를 먼저 갱신한다. "첫 등장"이 "N일차 파트 M"인 행은 1판에서 온 것으로, 해당 장을 쓸 때 장 번호로 고친다.

| 용어 | 영문 | 원본의 다른 표기 | 정의 | 첫 등장 |
| --- | --- | --- | --- | --- |
| LLM | large language model | 모델, 언어 모델 | 대량의 글로 학습해, 주어진 글 다음에 올 토큰을 예측하는 방식으로 글을 생성하는 모델 | 1장 |
| API | application programming interface | 창구, 접점 | 프로그램이 다른 프로그램의 기능을 정해진 형식으로 요청하고 결과를 받는 인터페이스 | 1일차 파트 1 |
| SDK | software development kit | 클라이언트 | API를 프로그래밍 언어에서 쉽게 부를 수 있게 만든 라이브러리. 요청 조립, 오류 변환, 재시도를 대신한다 | 5장 |
| API 키 | API key | 키 | API를 호출한 사람을 식별하는 문자열. 사용 기록과 요금이 키별로 집계된다 | 2일차 파트 1 |
| 환경 변수 | environment variable | | 운영체제가 프로그램에 넘겨주는 이름과 값의 쌍. 키처럼 코드에 적으면 안 되는 값을 두는 곳 | 2일차 파트 1 |
| 요청 | request | 호출 | API에 보내는 한 번의 호출 내용. 모델 이름, 메시지 목록, 옵션이 들어 있다 | 5장 |
| 응답 | response | 응답 객체 | 요청에 대해 API가 돌려주는 결과. 응답 텍스트, 토큰 사용량, 종료 이유가 들어 있다 | 5장 |
| 토큰 | token | | 모델이 글을 읽고 쓰는 단위. 단어보다 작은 조각인 경우가 많고, 길이 제한과 요금을 토큰 수로 계산한다 | 1장 |
| 입력 토큰 | input tokens | | 요청에 담아 보낸 글(시스템 프롬프트와 대화 내용)의 토큰 수 | 3장 |
| 출력 토큰 | output tokens | | 모델이 생성한 글의 토큰 수. thinking 과정에서 쓴 토큰도 포함한다 | 1일차 파트 1 |
| 컨텍스트 윈도우 | context window | 컨텍스트 창, 입력 한도 | 모델이 한 번의 요청에서 다룰 수 있는 토큰 수의 상한. 입력과 출력을 합쳐 센다 | 3장 |
| 최대 출력 토큰 | max tokens | 응답 길이 상한, 출력 상한, max_tokens | 한 번의 응답에서 모델이 생성할 수 있는 토큰 수의 상한. 요청할 때 정한다 | 1일차 파트 1 |
| 종료 이유 | stop reason | stop_reason, 끝난 이유 | 모델이 생성을 멈춘 이유. 정상 종료, 최대 출력 토큰 도달, 거절 등이 있다 | 5장 |
| 메시지 | message | messages | 대화의 한 마디. 누가 말했는지(역할)와 내용으로 이루어진다 | 3장 |
| 역할 | role | | 메시지를 말한 쪽. 사용자(user), 모델(assistant), 시스템(system)이 있다 | 3장 |
| 채팅 템플릿 | chat template | | 메시지 목록을 역할 표시 토큰으로 감싸 모델이 학습한 형식의 글 한 덩어리로 바꾸는 규칙. 모델마다 다르다 | 3장 |
| 시스템 프롬프트 | system prompt | system, 규칙 | 대화 전체에 적용할 모델의 입장(역할 지정), 규칙, 출력 형식을 적은 글 | 3장 |
| 대화 이력 | conversation history | history | 지금까지 주고받은 메시지의 목록. 대화를 이어 가려면 요청마다 다시 보낸다 | 3장 |
| 무상태 | stateless | 상태 없음, 저장하지 않습니다 | 서버가 이전 요청의 내용을 기억하지 않는 성질. 필요한 정보는 요청마다 모두 보내야 한다 | 3장 |
| 샘플링 | sampling | | 모델이 다음 토큰을 확률 분포에 따라 무작위로 뽑는 과정. 같은 입력에도 응답이 달라지는 원인이다 | 1장 |
| temperature | temperature | 온도 | 샘플링 전에 logit을 나누는 값. 낮을수록 확률이 1위 토큰에 몰리고, 높을수록 고르게 퍼진다 | 1장 |
| 토크나이저 | tokenizer | | 글을 토큰으로 나누고 각 토큰을 번호로 바꾸는 프로그램. 모델마다 따로 있어 같은 글도 모델에 따라 토큰 수가 다르다 | 1장 |
| 어휘 | vocabulary | 단어 사전, vocab | 토크나이저가 아는 토큰 전체의 목록. 토큰마다 번호가 붙어 있다 | 1장 |
| 토큰 ID | token ID | 토큰 번호 | 어휘에서 토큰에 붙은 번호. 모델은 글자가 아니라 이 번호의 나열을 입력으로 받는다 | 1장 |
| BPE | byte pair encoding | | 글자에서 시작해 자주 붙어 나오는 쌍을 하나의 토큰으로 합치는 일을 반복해 어휘를 만드는 방법 | 1장 |
| 바이트 단위 BPE | byte-level BPE | | 글자 대신 UTF-8 바이트에서 시작하는 BPE. 어떤 글이든 토큰으로 나눌 수 있지만, 어휘에 없는 글자는 바이트 조각 여러 개가 된다 | 1장 |
| 트랜스포머 | transformer | | 지금의 LLM 대부분이 쓰는 신경망 구조. 어텐션과 계산 층을 여러 번 쌓아, 토큰마다 앞 내용을 반영한 벡터를 만든다 | 1장 |
| 어텐션 | attention | | 각 위치가 앞 토큰들의 정보를 얼마씩 섞을지 가중치로 정하는 계산 | 1장 |
| 파라미터 | parameter | 매개변수 | 학습으로 정해지는 모델 내부의 숫자. 모델 크기를 파라미터 개수로 말한다. API 요청의 옵션(파라미터)과는 다른 말이다 | 1장 |
| logit | logit | | 모델이 어휘의 토큰마다 내는 점수. 확률이 되기 전의 값으로, 음수도 될 수 있다 | 1장 |
| softmax | softmax | | 점수 목록을 모두 0과 1 사이이고 합이 1인 확률 분포로 바꾸는 계산. 점수 차이가 클수록 확률 차이가 더 커진다 | 1장 |
| 확률 분포 | probability distribution | | 가능한 결과마다 확률을 붙인 것. 여기서는 어휘의 토큰마다 다음에 올 확률을 붙인 것이다 | 1장 |
| greedy decoding | greedy decoding | 탐욕적 디코딩 | 다음 토큰으로 언제나 확률이 가장 높은 토큰을 고르는 방법 | 1장 |
| top-p | top-p, nucleus sampling | 누클리어스 샘플링 | 확률이 높은 토큰부터 더해 누적 확률이 p에 이를 때까지의 후보만 남기고 그 안에서 샘플링하는 방법 | 1장 |
| top-k 샘플링 | top-k sampling | | 확률이 높은 토큰 k개만 남기고 그 안에서 샘플링하는 방법. 검색 결과의 top-k와 다른 말이다 | 1장 |
| 시드 | seed | random seed | 난수를 만드는 시작값. 같은 시드로 같은 계산을 하면 같은 난수가 나와 결과를 재현할 수 있다 | 1장 |
| thinking | thinking | 추론, 생각 | 모델이 응답을 쓰기 전에 내부적으로 문제를 풀어 보는 과정. 출력 토큰으로 계산된다. 학습된 모델을 실행한다는 뜻의 추론(inference)과 다른 말이다 | 2장 |

| 모델 등급 | model tier | 경량, 중형, 대형 | 같은 제공사의 모델을 능력과 가격으로 나눈 구분. 교재에서는 소형, 기본, 대형으로 부른다 | 1장 |
| 레이트 리밋 | rate limit | 요청 한도, 속도 제한, 429 | 일정 시간 동안 보낼 수 있는 요청 수나 토큰 수의 상한. 넘으면 429 오류가 난다 | 5장 |
| 상태 코드 | status code | | 서버가 요청 결과를 알리는 세 자리 숫자. 2xx는 성공, 4xx는 요청 쪽 문제, 5xx는 서버 쪽 문제다 | 5장 |
| 타임아웃 | timeout | 시간 제한, 시간 초과 | 응답 대기 시간의 상한. 넘으면 요청을 포기하고 오류로 처리한다 | 5장 |
