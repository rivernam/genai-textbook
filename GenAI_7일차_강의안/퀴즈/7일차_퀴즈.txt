── 파트 01 · AI 에이전트의 개념 ──

[1] (객관식) LLM 이 도구를 쓰게 하는 함수 호출(Function Calling) 방식에서, 모델과 애플리케이션 코드가 하는 일을 바르게 설명한 것은?
     A. 모델은 필요하면 요청에 포함된 도구 목록에 없는 함수도 새로 만들어 실행한다
     B. 모델은 호출할 함수와 인자를 고르고, 함수 실행은 애플리케이션 코드가 한다
     C. 모델이 함수의 코드를 직접 읽고 실행한 뒤 결과를 응답에 넣는다
     D. 모델이 함수를 실행하고, 애플리케이션 코드는 실행 결과를 화면에 보여 주기만 한다

     답 : 


[2] (객관식) 도구를 쓰는 AI 에이전트의 실행 루프(모델 호출 → 도구 실행 → 결과 전달의 반복)가 끝나는 경우로 옳은 것은?
     A. 모델이 도구를 더 호출하지 않고 글로만 응답하거나, 미리 정한 최대 반복 횟수에 이르렀을 때
     B. 모델의 응답에 글(text 블록)이 하나라도 들어 있을 때
     C. 호출한 도구가 오류를 돌려주었을 때
     D. 모델이 도구 목록에 있는 도구를 모두 한 번씩 호출했을 때

     답 : 


[3] (객관식) LLM 에이전트에서 별도의 도구(함수)로 처리할 일에 대한 설명으로 옳은 것은?
     A. LLM 은 숫자 계산을 전혀 하지 못하므로, 두 자리 수의 덧셈 같은 간단한 계산도 항상 틀린다
     B. 도구를 많이 제공할수록 모델이 알맞은 도구를 더 정확하게 고른다
     C. 도구에 알맞은 일은 큰 수의 곱셈 · 날짜 계산 · 정확한 데이터 조회처럼, 모델은 틀리기 쉽지만 코드로는 정확하게 처리할 수 있는 일이다
     D. 요약이나 문장 다듬기도 규칙으로 작성한 코드가 모델보다 정확하므로 도구로 처리하는 편이 알맞다

     답 : 


[4] (객관식) MCP(Model Context Protocol)에 대한 설명으로 옳은 것은?
     A. 모델이 도구를 고르는 능력을 높이기 위해 모델을 다시 학습시키는 방법이다
     B. 함수 호출 없이 모델이 사내 데이터베이스에 직접 접속해 값을 읽는 방식이다
     C. MCP 를 쓰면 모델이 도구를 고르는 방식 자체가 함수 호출과 완전히 달라진다
     D. AI 앱과 도구를 연결하는 표준 규격으로, MCP 서버가 도구 목록과 도구 정의를 제공하고 도구 실행도 맡는다

     답 :

     C. 끝나지 않는 반복 → 실행 루프의 최대 반복 횟수와 도구 호출 수 상한

     C. 도구 함수의 코드와 주석
     D. 도구 함수가 실행되는 데 걸리는 시간

[7] (객관식) 문서 검색 도구와 데이터베이스 조회 도구를 함께 제공했더니, 「지난달 불량 건수는?」 같은 집계 질문에 모델이 문서
     검색 도구를 골랐다. 이 선택을 바꾸는 데 효과가 있는 수정은?
     A. 비슷한 검색 도구를 몇 개 더 제공해 모델이 고를 후보를 늘린다
     B. 문서 검색 함수의 코드 안 주석에 용도를 자세히 적는다
     C. 두 도구의 이름을 tool_1, tool_2 처럼 번호로 바꿔 구분한다
     D. 각 도구의 설명에 어떤 질문에 쓰는지와 그 도구로 찾을 수 없는 정보를 함께 적는다

     답 : 


[8] (객관식) 정해진 절차로 검색하는 기본 RAG 와, 검색을 도구로 주고 모델이 스스로 검색하게 하는 에이전틱 RAG 를 비교한
     설명으로 옳은 것은?
     A. 에이전틱 RAG 는 한 질문에 검색을 한 번만 할 수 있다
     B. 기본 RAG 는 검색어와 횟수를 코드가 정해 두고, 에이전틱 RAG 는 모델이 검색어를 정하고 결과가 모자라면 다시 검색한다
     C. 에이전틱 RAG 는 검색을 모델이 정하므로 호출 수와 비용이 기본 RAG 보다 항상 적다
     D. 기본 RAG 도 검색 결과가 모자라면 모델이 스스로 검색어를 바꿔 다시 검색한다

     답 : 


[9] (객관식) RAG 응답에 붙은 출처(문서번호)가 그 실행의 검색 결과에 실제로 있었는지 코드로 대조했다. 이 검증에 대한 설명으로 옳은 것은?
     A. 인용한 문서번호가 실제 검색 결과에 있었는지는 확인할 수 있지만, 응답의 문장이 그 문서와 같은 뜻인지는 확인하지
        못한다
     B. 문서번호가 검색 결과와 맞으면 응답 내용도 맞다고 볼 수 있다
     C. 문서번호가 검색 결과에 없으면, 응답 내용은 틀린 것으로 확정할 수 있다
     D. 출처를 적는 형식이 응답마다 제각각이어도 코드는 문서번호를 항상 정확히 찾아낸다

     답 : 


[10] (객관식) 에이전트가 호출한 도구에서 실행 오류가 났고, 애플리케이션 코드가 그 오류 내용을 도구 결과로 모델에 돌려주었다.
     이때의 설명으로 옳은 것은?

     B. 모델은 도구 결과에 담긴 오류 문구를 읽지 못하므로, 성공 결과를 받은 것과 같게 처리한다
     C. 모델이 오류 내용을 읽고 인자를 고쳐 다시 호출하거나 다른 도구를 고를 수 있다
     D. 오류를 돌려주면 실행 루프가 그 자리에서 자동으로 끝난다

[12] (객관식) 업무용 에이전트의 시스템 프롬프트에 「근거를 문서에서 찾지 못하면 '판단 불가'라고 쓴다」는 지시를 넣는 주된
     목적은?
     A. 모델이 문서를 더 많이 검색하게 하려고
     B. 근거가 없는 부분을 일반 지식으로 그럴듯하게 채우는 환각을 줄이려고
     C. 판단 기준을 정해 두지 않으면 모델이 판단을 거절하므로, 거절을 줄이려고
     D. 출력을 사내 양식의 항목과 순서로 고정하려고

     답 : 


[13] (객관식) 개인정보 · 금지어 같은 사내 규칙을 업무용 에이전트의 시스템 프롬프트에 적었다. 이에 대한 설명으로 옳은 것은?
     A. 시스템 프롬프트에 적은 규칙은 모델이 항상 지키므로 출력을 따로 검사하지 않아도 된다
     B. 규칙은 사용자 메시지에 적을 때만 효과가 있고, 시스템 프롬프트에 적으면 무시된다
     C. 규칙을 적어도 모델이 어길 수 있어, 규칙을 지켰는지는 출력을 검사해야 알 수 있다
     D. 모델은 학습 단계에서 개인정보를 지우도록 배웠으므로, 입력에 개인정보가 섞여 있어도 출력에 옮기지 않는다

     D. 정상 케이스는 실패를 유도하지 않으므로 프롬프트를 고쳐도 결과가 바뀌지 않는다
